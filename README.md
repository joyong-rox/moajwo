# 모아줘 (Moajwo) — 문서취합 자동화 도구

부처·시도·시군구에서 제각각의 양식으로 모은 통계 파일(xlsx·xls·csv)을 **한 장의 표준 결과**로 모아 주는 도구입니다.
로컬 폐쇄망에서 동작하며, 사람이 하던 "양식 맞추기 → 합계·누락 확인 → 이름 통일 → 붙여넣기"를 자동화하고
사람은 확인이 필요한 항목만 승인합니다.

- **파싱**: 제목·설명 행 아래 숨은 머리글(최대 100행), 2~3단 머리글, 병합 셀, 소계·합계·주석 행, 결측 표기(`-`, `x`)를 알아봅니다.
- **열 매핑**: 표준 사전 정확 일치 → 문자열·임베딩(bge-m3) 유사도 → 로컬 LLM(Qwen 7B) 순서로 열 이름을 표준 항목에 연결하고, 사용자가 확정한 매핑을 학습합니다.
- **통합 전 검증**: 합계 불일치·필수 기관 누락·기간 불일치는 차단, 전월 대비 이상치·공백·단위 차이는 경고, 개인정보는 확인 요청.
- **용어사전**: 기관·자치단체 이름을 7자리 코드로 해석합니다 (약칭, 행정구역 개편 전후 이름, 유효기간 반영).
- **검토 → 통합 → 자동화**: 사전 검토 패널에서 승인·거부 → 원본 출처와 변경 이력이 남는 결과 엑셀 생성 → 같은 양식은 저장한 규칙으로 다시 실행.
- **계정·권한**: 최고 관리자(소유자)·일반 사용자, 회원가입 승인, 관리자 화면(`/moajwoAdmin`), 매핑 규칙 승격 심사, 홈 대시보드.

## 원칙

- **100% 로컬 구동 (기본값)**: 기본 설정에서는 외부 네트워크를 쓰지 않습니다. 임베딩·LLM은 같은 PC(또는 내부망)의 Ollama, 행정동 코드표 등 참조 데이터는 저장소에 들어 있고, 웹·API 포트는 `127.0.0.1`에만 열립니다. 업로드한 파일과 DB는 Docker 볼륨에만 저장됩니다.
- 기본은 외부 API 미사용(폐쇄망): LLM·임베딩 모두 로컬 Ollama. 소유자가 「설정 > LLM 제공자」에서 직접 고른 경우에만 열 매핑 판정에 외부 API(OpenAI·Anthropic) 또는 Custom Endpoint를 씁니다 (아래 「LLM 제공자 설정」).
- 업로드된 원본 파일은 읽기 전용이며, 결과물은 항상 새 파일로 생성합니다.

## 실행 (Docker Compose)

준비물: Docker (Docker Desktop), [Ollama](https://ollama.com) — 인터넷이 되는 곳에서 모델을 한 번 받아 두면 이후 폐쇄망에서 씁니다.

```sh
ollama pull bge-m3        # 임베딩 (열 이름 유사도)
ollama pull qwen2.5:7b    # 로컬 LLM (사전·유사도로 못 정한 열만)
```

```sh
docker compose up -d --build
curl http://localhost:8000/health   # {"status":"ok","database":"ok"}
# 웹 화면: http://localhost:8080
```

- 백엔드는 호스트의 Ollama(`http://host.docker.internal:11434`)를 씁니다. 주소·모델은 환경변수 `OLLAMA_BASE_URL`, `OLLAMA_EMBED_MODEL`, `OLLAMA_LLM_MODEL`로 바꿉니다. Ollama가 꺼져 있어도 업로드·사전 매핑·검증·통합은 되고, 유사도·LLM 단계만 건너뜁니다 (열 매핑 결과에 안내가 표시됩니다).

### 최초 소유자(최고 관리자) 계정 만들기

1. 처음 `http://localhost:8080`에 접속하면(계정 0개) **최고 관리자 계정 만들기** 화면이 열립니다. 화면에 "처음 생성하는 소유자 계정은 이 서비스의 최고 관리자입니다. 사용자 가입 승인, 계정 관리 및 서비스 설정을 담당합니다."를 안내합니다.
2. 아이디·이름·비밀번호(8자 이상)를 입력하면 최고 관리자 계정이 만들어지고 승인 대기 없이 바로 로그인됩니다. 이 화면은 최초 설정이 끝나면 다시 열리지 않습니다 (소유자를 이용 중지하거나 계정 수가 바뀌어도 열리지 않음). 동시에 여러 요청이 와도 소유자는 한 명만 생깁니다 (계정과 같은 트랜잭션에서 `app_settings`의 고정 키 `owner_setup`을 넣어 DB 기본 키로 막고, 늦은 요청은 409). 계정이 있는 기존 설치에는 마이그레이션 0015가 이 표시를 넣습니다.
3. 최초 설정이 끝나면 로그인 화면의 **회원가입**으로 누구나 본인 계정의 가입을 신청할 수 있습니다 (최초 설정 전에는 가입 불가 — 409). 새 가입은 항상 일반 사용자·승인 대기이며, 최고 관리자가 「관리자 → 사용자·가입 신청」에서 승인해야 로그인할 수 있습니다. 최고 관리자가 계정을 직접 추가할 수도 있습니다 (일반 사용자만, 승인 여부를 반드시 선택).

### 기본 Seed 데이터 (마이그레이션)

- 백엔드 컨테이너는 **기동할 때마다 `alembic upgrade head`를 자동 실행**하므로, 새 버전을 받아 `docker compose up -d --build`만 하면 기본 데이터까지 적용됩니다. 기존 DB(볼륨)도 그대로 두고 빠진 단계만 적용합니다.
- 적용 확인: `docker compose exec backend alembic current` → `0018_mapping_analyses (head)`
- 컨테이너 없이 개발할 때: `cd backend && alembic upgrade head`
- 기본 데이터는 사용자가 이미 올린 항목(같은 7자리 코드·같은 이름의 현행 항목)을 덮어쓰지 않고, 해석 순서에서도 사용자 별칭·항목이 먼저입니다. 목록은 아래 「DB 마이그레이션」.

- 백엔드 컨테이너는 기동 시 `alembic upgrade head`를 실행한 뒤 서버를 띄웁니다.
- SQLite DB와 업로드 파일은 `moajwo-data` 볼륨(`/app/data`)에 저장됩니다.
- 포트는 `127.0.0.1`에만 바인딩됩니다.
- 처음 접속하면(계정 0개) **최고 관리자 계정 만들기** 화면이 열립니다. 다른 사람은 회원가입 후 최고 관리자의 승인을 받습니다.

## 업로드와 파싱 (`POST /files`)

- 필드 `files`로 xlsx / xls / csv 여러 개 업로드 (요청당 20개, 파일당 50MB).
- 원본은 `data/uploads/<uuid>.<ext>`에 새 파일로 저장 후 읽기 전용으로 바꾸고, 메타데이터는 `source_files`에 기록합니다.
- 파싱 규칙 ([backend/app/parsing.py](backend/app/parsing.py)) — 정부부처·시도/시군구 통계표 양식 기준
  - 헤더: 머리글 후보는 위에서부터 **최대 100행**, 그 뒤 첫 데이터 행은 **최대 200행** 안에서 찾습니다 (100행째 머리글 + 101행 데이터 같은 경계용. 글자만 있는 긴 목록을 끝까지 훑거나 멀리 떨어진 숫자 한 줄 때문에 본문 행을 머리글로 고르지 않도록 제한). 첫 데이터 행(연도가 아닌 숫자가 처음 나오는 행) 위의 머리글 후보 중 서로 다른 텍스트 셀이 가장 많은 행. 제목·작성일·빈 행·`검색기간 : 202608` 같은 `항목 : 값` 설명 행은 건너뜁니다 (정부 양식은 머리글이 7~8행에 있기도 함). 찾지 못하면 예전처럼 1~3행 중에서 고릅니다.
  - 머리글은 최대 3행까지 이어 붙입니다: 가로 병합 그룹(아래 2단 헤더)이나 `구별/차종별`처럼 위·아래 줄에 나뉘어 적힌 머리글. `총   계`처럼 정렬용으로 띄운 글자는 `총계`로 붙입니다. 머리글 행은 `계`·`총계` 같은 글자가 있어도 소계 행으로 세지 않습니다.
  - 설명 시트 건너뜀: 시트 이름에 `메타`·`설명`·`안내`가 들어가면(KOSIS `메타정보` 등) 읽지 않고 업로드 결과에 「설명 시트 건너뜀」으로 알립니다. 시트가 전부 설명 시트면 그대로 읽습니다.
  - 2단 헤더: 가로 병합 그룹 행(예: `인구`) 아래에 하위 헤더(예: `2025`, `남/여/계`)가 있으면 합쳐 `인구_2025`처럼 열 이름을 만듭니다
  - 병합 셀: 범위 전체를 왼쪽 위 값으로 채움 (ffill). 시도 칸이 세로 병합돼 있으면 동명 시군구(서울/부산 강서구 등)가 구분됩니다
  - 머리글 가로 병합으로 생긴 복제 열은 버립니다: 머리글 전체 의미(구분 번호를 붙이기 전 이름)가 같은 구간(`자가용`, `자가용_2`, `자가용_3`)에서 머리글 칸이 병합으로 채워졌고 본문 값도 모든 행에서 앞 열과 같으면 하나만 남깁니다. `인구_2024`·`인구_2025`처럼 머리글 의미가 다른 열은 값이 같아도 남깁니다. 값이 하나라도 다른 열(예: `시군구` 병합 아래 `천안시 | 동남구`의 구 이름)은 데이터라서 남기고, 남는 열의 이름은 바꾸지 않습니다(이미 저장한 매핑 확정과 맞춤). 병합이 아닌 같은 이름 열(CSV 등)은 그대로 둡니다.
  - 숫자: `1,234`, `2 100 000`, ` 750 ` 등은 숫자로 변환. 천 단위 구분이 틀린 값(전화번호 등)은 문자열 유지
  - **코드·번호·시각 열은 글자 그대로** (열 전체를 같은 기준으로): 열 이름에 `코드`·`번호`·`구분`·`우편`·`전화`·`연락처`·`일련`·`시각`·`ID`가 있거나, 앞자리 0이 있는 숫자 글자(`0900`, `00210`)가 섞인 열. 같은 열에서 `0900`은 글자, `1800`은 숫자가 되는 뒤섞임과 코드의 앞자리 0 손실을 막습니다. 천 단위 구분(`1,000`)이 쓰인 열은 수량으로 보고 숫자로 바꾸며, 엑셀에 숫자로 저장된 셀은 그대로 둡니다.
  - 결측 표기: `-`, `x`, `…`, `·` 등은 원본 그대로 두고 결측으로 표시 (0과 구분)
  - CSV 구분자(`,` `;` 탭 `|`)는 추측하고, 따옴표 규칙은 표준(RFC 4180: `"`로 감싸고 `""`로 이스케이프)으로 고정합니다 (값 안의 쉼표·따옴표가 있어도 열이 밀리지 않음).
  - CSV 인코딩: chardet 신뢰도 0.5 이상이면 채택, 아니면 EUC-KR → CP949 → UTF-8 순서
  - 행 구분 (행 수는 데이터 행만 셉니다)
    - 빈 행
    - 소계·합계 행: 셀이 `계`·`전국`·`total` 등이거나 `소계·합계·총계·누계`로 끝나는 라벨(`영업1팀 소계`, `합계(전체)`). `소계민원센터`처럼 이름 앞부분에 있는 단어는 지명으로 보고 데이터 행으로 둡니다.
    - 주석 행: 값이 하나뿐이고 `자료:`, `출처:`, `주:`, `주1)`, `※`, `*`, `(단위:` 로 시작
    - 데이터 행

## 열 매핑 (`POST /files/{id}/mapping`)

저장된 원본을 다시 파싱해 시트별 열 이름을 표준 사전([backend/app/standard_dictionary.json](backend/app/standard_dictionary.json))에 매핑합니다.

1. **사전 정확 일치**: 공백·가운뎃점·단위 괄호·연도를 무시하고 비교 → 자동 적용. `인구_2025`는 `인구수` + 연도 `2025`로 분리. 2단 헤더 일부만 일치하면 확인 대상.
   순서: 기본 표준 사전 → **전사 표준 사전**(최고 관리자 승인으로 승격된 이름, `standard_terms`) → 이 사용자가 학습한 별칭.
   - 구분 단어: 사전에서 `modifier`로 표시한 항목(관용·자가용·영업용)과 `계`·`소계`·`합계`·`총계`는 다른 항목과 함께 쓰이면 구분(qualifier)으로 붙습니다. `승용_관용`·`승용(관용)`·`관용(승용차)` → 승용차 (관용), `2024_승용차_계` → 승용차 (2024 계). 나머지 부분이 구분 단어뿐이면 자동 적용, 아니면 확인 대상(`인구_남`). 괄호 안이 사전 단어가 아니면 예전처럼 단위로 보고 무시합니다(`예산(백만원)`).
   - 차량 분야 기본 항목: 자동차 등록대수·승용차·승합차·화물차·특수차·이륜차·친환경차·전기차·수소차·하이브리드차·차종·용도·연료·관용·자가용·영업용.
   - 범용 항목: **합계**(`계`·`소계`·`총계`·`총합계`·`전체`, 구분 단어로도 쓰임 — `총계_계` → 합계, `승용_계` → 승용차 (계)), **등록건수**(`등록건수`가 유사도로 '자동차 등록대수'에 붙지 않도록 정확 일치).
   - **차량 문맥**: `화물`·`특수`처럼 차량 외 통계(물동량 등)에도 쓰이는 짧은 이름은, 같은 표의 열 이름에 `승용`·`승합`·`자동차`·`차량`·`이륜`·`차종`이 있을 때만 화물차·특수차로 자동 적용하고, 없으면 확인 대상으로 내립니다 (`화물차`처럼 뜻이 분명한 이름, 사용자가 확정한 열은 그대로).
   - **날짜 필터**: 샘플이 모두 날짜·기간 글자(`2026-08`, `2025-12-31`, `2012년`, `2026년 8월`)면 지역·용어 판별과 LLM 없이 기준일자·월·연도로 자동 적용합니다. 이 파일에서 사용자가 확정한 열, 사용자의 학습 별칭, 열 이름이 이미 날짜 항목(`월(Monthly)` 등)이면 그대로 둡니다. 숫자 셀(2024)과 8자리 숫자 글자(`20260831`, 코드와 겹침), 실제로 없는 날짜(`2026-13`, `2026-02-30`)는 날짜로 보지 않습니다. 통합 전 검증의 기간 검사도 같은 해석 규칙(`glossary.parse_date_value`)을 써서, 월 열의 `2026-08`·`2026년 8월`·날짜 값도 기간 근거로 씁니다.
   - 열 이름에 든 개인정보(이메일·휴대전화·주민등록번호 형식)는 LLM·임베딩 입력 전에 가립니다. 이런 열 이름은 개인 학습 별칭·전사 승격 후보로도 올리지 않습니다.
   - 화면·API에는 열 이름을 **마스킹한 표시 이름**(`column`)과 시트 안의 **열 식별자**(`column_id`, 예: `c3`)로 보냅니다. 확정 요청은 `column_id`로 받고(예전 방식의 원래 이름 `column`도 개인정보가 없는 이름이면 호환), 서버 안의 확정·학습 기록은 원래 이름 그대로라 기존 확정이 끊기지 않습니다. 업로드·매핑·확정·검토(중첩 payload·요청 조건, 과거 기록 포함)·검증 결과(기관·지역 값, 오류 근거 expected/actual, 참고, 저장된 과거 결과 포함)·자동화 규칙·실행 요약·변경 기록·승격 심사 응답에 같은 마스킹을 적용합니다. DB의 기록은 연결용 원문 그대로 두고 응답을 만들 때 가립니다. 개인정보 형식이 든 기관·지역 이름은 `registrable: false`로 표시되어 별칭으로 등록할 수 없고(별칭 등록 API도 422), 검토 완료 학습에서도 제외합니다. 업로드 원본 파일과 통합 결과 엑셀의 내용은 바꾸지 않습니다 (아래 「통합 결과 생성」의 개인정보 정책).
2. **유사도**: rapidfuzz 문자열 유사도 0.4 + bge-m3 임베딩 코사인 0.6 가중 평균
   - 0.90 이상이고 1·2위 차이 0.05 이상 → 자동 적용
   - 0.75 이상 → 사용자 확인 대상
   - 값 형식 규칙: 샘플이 모두 **행정안전부 행정동 코드표**(말소 포함)에 실제로 있는 2·5·8·10자리 코드면 `행정구역코드` (LLM 전에 결정). 5자리 이상이고 3개 이상 일치하면 자동 적용, 그 외 확인 대상. 숫자형 셀은 열 이름이 없거나 '코드'가 들어간 경우만
3. **LLM**: 1·2단계 미해결 열만, 한 번에 한 열씩 열 이름 + 샘플 값 5개 + 샘플 형식 힌트를 설정된 LLM 제공자(기본: 로컬 Ollama Qwen 7B)에 보냄. 결과는 항상 사용자 확인 대상(자동 적용하지 않음). 요청당 최대 15열.

- **확정과 학습** (`PUT /files/{id}/mapping/decisions`, `GET /mapping/fields`)
  - 화면에서 열마다 표준 항목(또는 '해당 없음')을 골라 확정하거나, 제안대로 일괄 확정합니다. 확정은 `mapping_decisions`에 저장되고 다시 분석해도 유지됩니다.
  - 확정한 열 이름은 `learned_aliases`에 **그 사용자의** 별칭으로 학습되어, 그 사용자의 다른 파일에서도 1단계에서 바로 자동 적용됩니다 (계정 도입 전에 학습한 별칭은 모두에게 적용). 표준 사전 파일은 수정하지 않습니다.
  - 여러 사용자가 같은 매핑을 승인하면 최고 관리자 심사를 거쳐 모두에게 적용되는 전사 표준 사전으로 승격됩니다 (아래 「매핑 규칙 승격」).
  - 헤더 없는 열('열3'), 이미 사전에 있는 이름, 사전의 다른 항목과 충돌하는 이름은 학습하지 않습니다(확정 자체는 저장).
- Ollama 설정: `OLLAMA_BASE_URL`(기본 `http://localhost:11434`, Compose에서는 `http://host.docker.internal:11434`), `OLLAMA_EMBED_MODEL`(기본 `bge-m3`), `OLLAMA_LLM_MODEL`(기본 `qwen2.5:7b`). 로컬/사설 주소가 아니면 호출을 거부합니다.
- 모델 준비(최초 1회): `ollama pull bge-m3 && ollama pull qwen2.5:7b`
- Ollama가 꺼져 있으면 임베딩 없이 문자열 유사도만 쓰고, LLM 대상 열은 미해결로 남깁니다.

### 열 매핑 작업 화면 (`/mapping`, `/mapping/common`)

업로드 카드의 「열 매핑 분석」은 분석만 실행하고 시트별 현황(사용자 확정·자동 제안·확인 필요·미해결)을 요약합니다. 확인·확정은 사이드바 **열 매핑** 화면에서 합니다.

- **단일 파일** (`/mapping?file=&sheet=s0&col=c3`): 상단에서 파일·시트를 고르고, 상태 필터·열 검색(열 이름 또는 연결된 표준 항목)으로 좁힙니다. 가운데는 엑셀형 미리보기(행 번호 = 원본 시트의 행, 열 위치 A·B… = 원본 시트의 열), 오른쪽은 선택한 열의 값 예시·추천 후보·분석 근거(기본 접힘)·표준 항목 검색·확정입니다. 머리글을 누르면(키보드 Enter 포함) 미리보기와 상세가 같은 열을 가리키고, 주소에 파일 id·시트 id(`s0`, `s1` … 시트 순번)·열 id가 남아 새로고침·직접 접근에도 같은 열을 엽니다. 1100px 이하에서는 열 목록에서 고른 뒤 상세를 보고, 미리보기는 따로 엽니다.
  - 미리보기는 **파싱 후 정리된 값**입니다 (머리글 여러 줄을 합친 이름, 병합 칸은 채운 값, 머리글 병합으로 생긴 복제 열 제외). 원본 셀 서식·수식·숨김 행은 보이지 않고 원본 파일은 바뀌지 않습니다. 한 번에 최대 200행(화면은 50행씩)만 보냅니다 (`GET /files/{id}/preview?sheet_id=&offset=&limit=`).
  - 시트는 `sheet_id`, 열은 `column_id`로만 가리킵니다. 화면·응답의 파일·시트·열 이름은 개인정보 형식을 가린 **표시용**이고(파일 목록의 `display_name`), 원래 이름은 서버 안에서만 확정값과 연결할 때 씁니다 — 가린 이름이 겹치거나 원래 이름과 달라도 id로 정확한 시트를 찾습니다. 기존 `PUT /files/{id}/mapping/decisions`도 `sheet_id`를 받습니다(`sheet` 이름은 호환용).
  - 미리보기와 매핑의 파일·시트·열 구성이 다르면(파서 변경 등) 선택·확정을 막고 다시 분석하라고 안내하며, 시트를 바꾸면 선택을 해제합니다. 파일·시트를 바꾸는 중에 늦게 도착한 이전 파일·시트의 응답(미리보기·매핑·분석·저장 결과)은 화면에 반영하지 않습니다 — 저장은 요청 당시의 파일·열에만 됩니다.
  - 한 열 확정도 일괄 확정과 같은 API로, 화면에서 본 확정값을 기대값으로 보냅니다. 그 사이 다른 탭·일괄 확정이 같은 열을 바꿨으면 덮어쓰지 않고(409) 최신 상태를 다시 불러옵니다.
  - '자동 제안'(확정 전)과 '사용자 확정'을 구분해 표시하고, 후보 점수는 "유사도 참고값"으로만 보여 줍니다(정답 확률 아님). 표준 항목 설명·다른 이름은 사전에 있는 것만 표시합니다.
  - '해당 없음'으로 확정한 열은 통합 결과에 넣지 않고(통합 때 '원래 이름으로 포함'을 고르면 원래 이름으로), 확정하지 않은 '확인 필요'·'미해결' 열은 사전 검토에서 확인을 요청하며 '자동 제안'은 자동 적용 항목으로 들어갑니다.
  - 분석 결과는 파일·사용자마다 마지막 1건을 저장합니다 (`mapping_analyses`, 이미 마스킹한 응답, 같은 파일을 동시에 처음 분석해도 1행). 화면을 다시 열 때는 저장된 분석 + 지금의 확정값을 씁니다(`GET /files/{id}/mapping/latest`, 항상 200). **분석 기록이 없으면** 자동으로 분석하지 않고, 저장된 확정값은 '사용자 확정'으로, 나머지 열은 '미분석'으로 보여 줍니다(0018 반영 직후의 기존 파일). 화면을 여는 것만으로는 분석·확정·학습 기록을 쓰지 않습니다.
  - 큰 파일은 처음 열 때 원본을 한 번 파싱하고(예: 10만 행 CSV 약 12초), 같은 파일의 다음 쪽은 서버 메모리의 마스킹된 보기(파일 id·sha256 키, 최근 2개 파일, 파일당 300만 칸 이하)를 다시 씁니다. 같은 파일에 동시에 온 요청은 한 번만 파싱합니다. 300만 칸을 넘는 파일은 보관하지 않아 **쪽을 넘길 때마다 다시 파싱**합니다(격리 측정: 330만 칸 CSV 쪽마다 약 23초, 동시 요청은 차례로 처리). 이 상한은 보관 항목의 상한이며, 파싱 중에는 원본 크기에 비례한 메모리를 따로 씁니다.
  - '자동 제안 일괄 확정 준비'는 지금 시트의 **'자동 제안' 열만** 대상으로 합니다. '확인 필요'는 포함하지 않으며 열마다 직접 확인·확정합니다. 필터·검색으로 숨은 자동 제안이 포함되면 확인 화면에 그 수를 알립니다.
- **여러 파일 공통 검토** (`/mapping/common`, `POST /mapping/common`): 고른 파일(최대 20개)의 저장된 분석과 확정값만 모읍니다 — 화면을 열어도 다시 분석하거나 모델(임베딩·LLM)을 부르지 않으며, 분석 기록이 없는 파일은 제외하고 알려 줍니다. 단계 안내는 대상·처리·제외 파일 수를 나눠 보이고(예: 대상 5개 / 처리 0개 / 제외 5개), 처리한 파일이 없으면 '완료'로 표시하지 않고 이유와 다음 행동을 안내합니다. 일부만 처리했으면 '일부 확인'으로 표시합니다. 열 이름(정규화)으로 모은 뒤 다음처럼 나눕니다.
  - **공통 매핑 후보**: 2개 이상 파일에서 표준 항목·구분어·값 형태가 같고, 수량 열이면 단위와 흐름/시점 표기가 충돌하지 않는 열. 묶음마다 **확인한 근거**(열 이름·표준 항목·구분어·값 형태·단위·흐름/시점)를 보여 주며, 어느 파일에도 표기가 없어 확인하지 못한 근거는 '확인하지 못함'으로 적습니다.
  - **파일별 판단이 다른 항목**: 매핑·구분어·값 형태·단위가 다르거나, 단위 표기가 여러 개이거나 일부 파일에만 있거나, 흐름/시점이 섞였거나 한 표에 함께 있거나 일부 파일에만 있거나, `합계`·`계`·`구분`처럼 이름만으로 대상·단위를 알 수 없는 열 (근거가 없는 파일을 빼고 나머지만 비교해 '같음'으로 보지 않음)
  - 수량 열 = 값이 숫자이거나, 글자로 저장됐어도(`010`) 수량 표준 항목(인구·예산·차량 대수 등)으로 매핑된 열. 시트 단위는 수량 열에만 적용하고 기관명 같은 글자 열에는 적용하지 않습니다.
  - 단위: 제목·주석의 '단위: …' 선언을 모두 읽습니다. 선언이 둘 이상이면서 단위가 다르거나 한 선언에 여러 단위(`명, %`)가 있으면 첫 값을 고르지 않고 '불명확'으로 둡니다. 단위·사유 문자열의 개인정보 형식(이메일·전화번호 등)은 서버에서 가린 뒤 응답합니다.
  - 흐름/시점: 열 이름과 표 제목에서 흐름 표기(`신규`·`전입`·`발생`·`실적`·`건수` 등)와 시점 표기(`등록대수`·`보유`·`누계`·`잔액` 등)를 찾습니다. 제목의 '현황'만으로는 시점으로 보지 않으며, 둘 다 있으면(예: '자동차 신규 등록 현황'의 `등록대수`) 판단할 수 없음으로 둡니다.
  - **미해결 항목**: 표준 항목 제안이 없는 열 / **특정 파일에만 있는 항목**: 한 파일에만 있는 이름
  - 다른 연도 열(`인구_2024`·`인구_2025`)이나 용도가 다른 식별자(`관리번호`·`발급기번호`·`기관코드`)는 이름이 달라 서로 묶이지 않습니다. 개인정보 형식이 가려진 열 이름은 묶지 않습니다.
  - 공통 후보 묶음의 기본 선택은 '자동 제안'이면서 확정 전인 열뿐입니다. '확인 필요' 열은 직접 골라야 포함됩니다.
- **선택 일괄 확정** (`POST /mapping/batch/preview` → `POST /mapping/batch/apply`, 대상은 `file_id`·`sheet_id`·`column_id`): 확정 전에 파일·시트·원본 열, 열마다 **지금 상태(자동 제안·확인 필요 등)와 제안 근거**, 기존 매핑·바꿀 매핑·적용 여부와 제외 사유, 선택 수와 실제 적용 수를 보여 줍니다(미리보기는 저장하지 않음). 새로 확정할 행도 하나씩 뺄 수 있고, 기존 사용자 확정은 행마다 '기존 확정을 바꿈'을 골라야 바뀝니다. 적용할 때 서버는 먼저 쓰기 트랜잭션 밖에서 파일을 읽어 시트·열·표준 항목을 확인하고(큰 파일 파싱 포함), 그다음 쓰기 잠금을 잡은 짧은 트랜잭션 안에서 파일 소유권(최고 관리자도 남의 파일은 조회 전용)과 현재 확정값만 다시 확인한 뒤 저장합니다 — 큰 파일 여러 개를 처음 적용하는 동안에도 다른 사용자의 로그인·저장이 잠금 오류로 실패하지 않습니다 — 확인 뒤 다른 요청이 확정값을 바꿨거나 하나라도 적용할 수 없으면 아무것도 저장하지 않고(409) 사유를 보여 줍니다. 같은 요청을 다시 보내면 '이미 같음'으로 처리해 중복 저장하지 않습니다. 학습 별칭은 사용자·이름당 1건, 승격 근거(`mapping_approvals`)는 같은 사용자가 여러 파일에서 승인해도 1명으로 셉니다. 저장한 매핑은 단일 파일 화면에서 다시 바꿀 수 있습니다(되돌리기 기능은 없음).

### 데이터 통계 분석 (`/analysis`, 1차)

화면 이름은 2026-10-22에 '데이터 분석'에서 바꿨습니다 — 열 이름을 표준 항목에 연결하는 '열 매핑 분석'과 구분하려는 것이며 주소·기능은 같습니다.

열 매핑을 마친 자료로 합계·평균(산술)·최솟값·최댓값·유효 숫자 개수를 구하고, 지역·기관·구분·기간별로 묶거나 결과 열을 구간으로 나눕니다. 수식 입력·임의 코드 실행·차트·예약 실행은 없고, 비율·증감률·가중평균·단위 환산·기간 합산은 후속 기능입니다.

- **흐름**: 항목과 파일 고르기(`GET /analysis/fields`·`/analysis/sources`, DB의 확정 매핑만 읽음) → 대상 확인(`POST /analysis/preview`, 계산·저장 없음) → 그룹·필터·계산 방식·구간 설정 → 실행(`POST /analysis/run`) → 결과·제외·근거 행(페이지 단위) → Excel(결과·조건·제외·근거 행). 열 매핑 화면의 '이 항목으로 데이터 통계 분석'(조회 전용 파일에서는 이동 대신 사유만 보임), 공통 검토의 '고른 파일로 데이터 통계 분석'은 선택값만 넘깁니다 — 항목을 고르기 전에도 넘겨받은 파일을 보여 줍니다.
- **열 고르기**: 화면 위치·열 이름이 아니라 파일·시트·열 식별자와 **사용자가 확정한** 표준 항목으로 고릅니다 ('자동 제안'은 쓰지 않음). 저장된 열 매핑 분석 기록이 없어도 확정 매핑이 있으면 씁니다. 이름이 달라도 같은 항목으로 확정됐으면 함께 계산하되, 열 이름의 연도·2단 머리글의 각 부분·괄호 안 사전 단어(구분)가 다르면 따로 계산합니다.
- **숫자가 맞아도 의미가 틀린 결과를 막는 규칙** (서버가 판정):
  - 단위: 표 제목·주석의 '단위: …'나 열 이름 괄호에서 확인된 같은 단위끼리만 계산합니다. 섞이면 계산할 단위를 고르게 하고 다른 단위의 자료는 사유와 함께 뺍니다 (자동 환산 없음). 단위 표기가 없으면 사용자가 그 시트의 단위를 적어야 쓰며, 조건에 '사용자 확인'으로 남깁니다.
  - 기간: 행의 연도·월·기준일 열, 없으면 시트명·제목, 그것도 없으면 파일명에서 확인합니다 (파일명의 날짜는 발행·작성 시점일 수 있어 제목의 기준 시점과 같은 뜻으로 비교하지 않고, 쓴 근거를 표시). 기간이 여럿이면 기간별로 나눠 더하지 않습니다 (시점 값을 월별로 더해 연간 값으로 만들지 않음). 연도·월·기준일 열끼리 맞지 않는 행(연도 2025 · 월 2026-09 등)이 있거나 시트명·제목의 기간이 서로 다르면 추정하지 않고 실행을 막습니다. 시점 값(인구·등록대수 등)은 같은 달이라도 기준일이 다르면 함께 계산하지 않습니다 (일 단위 분석은 지원하지 않음). 이 기준일 검사는 사용자가 조건(필터·숫자 범위)으로 뺀 행만 빼고, 시스템이 자동으로 뺀 행(상위·하위 지역, 합계 행 등)까지 근거로 봅니다 — 자동 제외가 충돌을 가리지 않게. 사용자 조건(지역·기관·기간·숫자 범위)은 시스템 제외 사유와 따로 합계·소계 행에도 같게 적용하므로, 사용자가 조건으로 뺀 합계·소계 행은 기준일 근거에서도 빠집니다. 숫자 범위도 지역·기간 필터와 같은 시점에 적용해, 반복·중복·상위·하위 판정과 계산이 모두 사용자 조건이 남긴 행만 씁니다 — 같은 행을 남기는 숫자 필터와 지역 필터는 같은 판정·결과를 냅니다. 기간을 못 찾으면 사용자가 적어야 씁니다.
  - 집계 대상: 지역·기관·구분·기간 열로 한 행이 무엇인지 확인합니다. 지역은 시도·시군구 열로 나눠 적었든 '행정구역' 한 열에 적었든 행정구역 코드로 비교합니다 (정식 명칭으로만 — 약칭은 글자 그대로 비교). 파서가 합계·소계로 분류한 행, '계·합계·전체'로 적힌 행은 뺍니다.
  - 상위·하위 지역: 같은 기간·같은 구분(기관·차종 등) 안에서만 비교합니다. 하위 지역 합계가 상위 지역(시도·전국) 값과 **정확히** 같으면 상위 행을 중복으로 빼고(허용 오차 없음 — 정수는 1원·1명 차이도 다름, 소수는 원본에 적힌 자릿수로 비교해 이진 표현 오차만 없앰), 시점 값은 기준일이 다른 행끼리 상위·하위로 판정하지 않으며, 다르거나 값이 빠져 확인할 수 없으면(하위 지역 일부만 있음 등) 실행을 막고 집계 수준(하위 지역만 / 상위 지역만)을 고르게 합니다. '하위 지역만'을 골랐는데 합계가 다른 곳이 있으면 결과를 '선택한 지역 수준 집계'로 표시하고, 상위 값·하위 합계·차이를 화면 조건과 Excel '조건' 시트에 남깁니다.
  - 중복: 같은 내용(sha256)의 파일이나, 같은 대상(기간·지역·기관·구분)이 다른 자료에도 있으면 실행하지 않고 출처·값을 보여 준 뒤 사용자가 고르게 합니다 (임의 삭제·최신 우선 없음). 한 시트 안에서 같은 대상이 반복되면 중복된 통계인지 서로 다른 기록인지 알 수 없으므로, 사용자가 '반복 행은 서로 다른 기록 — 모두 더함'을 고르기 전에는 계산하지 않습니다 (고른 뒤에도 다른 자료와의 중복 검사는 그대로).
  - 결측: 빈칸·비공개 표기('-', 'x', '…', '비공개' 등)·숫자가 아닌 값·가린 개인정보는 0으로 바꾸지 않고 사유와 함께 뺍니다. 그런 값이 있으면 그 그룹과 결과를 '부분 집계'로 표시합니다. 유효한 숫자가 없으면 평균·최솟값·최댓값·합계를 '계산할 값 없음'으로 둡니다.
  - 평균은 그룹마다 유효한 숫자의 합 ÷ 그 개수입니다 (파일별 평균을 다시 평균하지 않음, 분모 표시).
  - 구간: 적용할 결과 열과 경계 포함 여부를 정하고, 겹치는 구간은 받지 않습니다. 어느 구간에도 들지 않으면 '미분류'입니다. 구간은 번호로 세므로, 이름이 같거나 가린 뒤 같아져도 서로 합쳐지지 않습니다 (보여 줄 때 '(2번 구간)'처럼 번호를 붙임).
  - 가린 값과 대상: 지역·기관·조직·부서·차종·용도·연료 값은 화면처럼 가린 값으로 보이지만, 가림으로 글자가 바뀐 칸은 서버 안에서만 쓰는 원문 구분 표지(프로세스마다 새로 만든 키의 HMAC — 저장·응답하지 않음)로 같은 대상인지 판정합니다. 가린 표시가 같아도 원문이 다르면 다른 그룹·다른 대상이고(반복·중복·상위·하위 판정 포함), 화면·저장·Excel에는 '가팀 k***@example.com (가림 구분 1)'처럼 그 결과 안에서만 통하는 번호를 붙입니다. 번호 없이 가린 값으로 고른 필터와 가린 뒤 같아진 서로 다른 열 이름 구분은 계산하지 않고 막습니다(409).
- **메일 통계 항목·합계 산식**: 발신·수신·외부·조회·용량·메일함 항목의 단위·성격(발생량/시점값)·산식과, 이름이 같아도 산식이 다른 합계를 알리는 규칙(통합 전 검사 경고 '합계 산식 확인 필요', 분석·통계 요약의 주의)은 [docs/MAIL_FIELDS.md](docs/MAIL_FIELDS.md)에 적었습니다.
- **원본 열 표시**: 표준 항목 이름('건수')만으로는 어느 지표('발신Mail건수')를 계산했는지 알 수 없어, 대상 확인·결과 화면·지난 결과 목록·Excel '조건' 시트에 계산한 원본 열(가린 이름, 시트 수)을 함께 적습니다. 이름이 서로 다르면 같은 지표인지 확인하라고 안내하고, 가린 뒤 같아진 서로 다른 이름은 '(가림 구분 n)'으로 나눕니다. 이 목록이 생기기 전에 저장된 결과는 저장된 입력의 열로 보여 줍니다(저장값은 바꾸지 않음). 파일별 시트로 묶기의 '통계 요약'도 같은 목록을 설정 화면·요약 시트·실행 기록에 남깁니다.
- **저장·재현**: 결과(`analysis_runs`)에 조건·사용한 파일 sha256·시트·열·그 시트의 확정 매핑·판정 정책(`analysis-policy-8`, 이전 결과는 저장 당시 정책 이름 그대로)·생성 시각을 함께 저장합니다. 결과 화면·페이지·Excel은 저장값으로 만들어, 나중에 매핑이 바뀌어도 과거 결과가 조용히 바뀌지 않습니다. 대상 확인 뒤 조건·파일·매핑이 바뀌면 실행을 거부합니다(409). 화면은 대상 확인 응답이 늦게 와도 그사이 바뀐 조건을 덮어쓰지 않고, 확인한 조건 그대로일 때만 실행합니다. 통합 실행·절약 시간 통계에는 넣지 않습니다.
- **권한**: 분석은 본인 파일로만 만듭니다 — 최고 관리자도 남의 파일로는 대상 확인·실행을 할 수 없습니다(403, 기록 없음). 결과는 본인 것만 보고, 최고 관리자는 남의 기존 결과를 조회·다운로드만 합니다. 요청마다 서버가 확인합니다. 파일·시트·열 이름, 사용자가 적은 구간 이름·필터 값·단위·구분, 메시지는 기존 개인정보 마스킹으로 가린 뒤 저장·표시·다운로드하고, Excel에 쓰는 글자는 수식으로 저장되지 않게 합니다.
- **부작용 없음**: 화면을 열거나 대상을 확인·실행해도 다시 분석·매핑 변경·학습·모델(임베딩·LLM) 호출이 일어나지 않습니다. 계산은 로컬 코드로 하고, 파싱·계산은 쓰기 트랜잭션 밖에서, 결과 저장만 짧게 씁니다.
- **입력 규모**: 한 번에 파일·시트 20개, 데이터 행 합계 30만 행, 그룹 5,000개까지 (넘으면 413/422로 안내). 근거 행·제외 행 목록은 처음 2만 행만 보관합니다 (계산은 전체 행, 사유별 건수는 전체). 결과 페이지를 넘겨도 다시 계산하지 않습니다.

## 통합 전 검증 (`POST /validation`)

검증 대상 파일, 전월 자료, 기준 기간(`YYYY` 또는 `YYYY-MM`), 필수 기관·지역 목록을 받아 결과를 **등급별로 분리**해 돌려줍니다. 원본과 파싱 결과는 바꾸지 않고 상태만 반환하며, 실행 기록은 `validation_runs`에 남습니다.

| 등급 | 항목 | 판단 |
| --- | --- | --- |
| 차단 (통합 불가) | 합계 불일치 | 소계·합계 행 vs 그룹 하위 행 합 (`서울특별시 \| 계`, `영업1팀 소계`, 전국·합계는 그룹 소계 + 미분류 행). 비율 열·개인정보(정수로 저장된 주민등록번호 포함)가 탐지된 열 제외, 반올림 허용 오차 = 하위 행 수 × 마지막 자리 ½, `-`는 0, `x`·`…`가 있으면 검사 생략 |
| 차단 | 필수 기관 누락 | 목록의 기관·지역이 기관/지역 열(또는 기관별 파일명)에 없음 |
| 차단 | 기간 불일치 | 연·월·기준일 열, 제목 행, 시트명, 파일명의 기간 ≠ 기준 기간 (기준 기간이 없으면 파일 간 기간이 다를 때) |
| 경고 (통합 진행) | 전월 대비 이상치 | 같은 기관·지역(시도+시군구 등) 행의 값 변화율이 임계값(기본 ±50%) 초과 |
| 경고 | 공백 값 | 매핑된 열의 빈 셀 (`-`, `x` 같은 결측 표기는 제외) |
| 경고 | 단위 추정 | 같은 항목의 단위가 다름(백만원 vs 천원), 값 규모가 300배 이상 차이, 금액 항목에 단위 표기 없음 |
| 경고 | 헤더 확인 필요 | 머리글을 찾지 못했거나, 실제 열 이름(`열N` 제외)이 2개 미만. 사전 검토 화면 맨 위에 따로 경고를 띄웁니다 |

- 상태: `blocked`(차단 있음) > `pii_confirmation_required`(미확인 개인정보) > `passed_with_warnings` > `passed`
- 검증에는 확정·자동 적용된 열 매핑만 쓰고 LLM은 호출하지 않습니다.
- 참고(notes): 검사할 수 없었던 이유. 상태에 영향 없음.
- 합계 검사 예외 (참고에 이유를 남김)
  - 누적 통계: 맨 위 합계 행 아래 데이터 라벨의 80% 이상이 시점(`1월`, `2026.08`, `2024년` 등)일 때, **열마다** 두 조건이 모두 있으면 그 열만 연말·말일 값으로 보고 월별 합과 비교하지 않습니다 (근거를 열별로 참고에 남김). ① 독립 근거: 그 열이 시점 값 항목(인구수·세대수·자동차 등록대수 등)으로 매핑됨, 합계 항목 열인데 같은 표의 다른 숫자 열이 모두 시점 값 항목, 열 이름의 시점 값 표기(`등록대수`·`잔액`·`누계` 등), 또는 파일명·시트명·제목의 표기(**숫자 열이 하나뿐일 때만** — 여러 열이면 어느 열을 뜻하는지 모호해 일괄 적용하지 않음). 열 이름에 흐름 표기(`신규`·`전입`·`증감`·`발생`·`건수` 등)가 있으면 차량·인구 항목으로 매핑돼 있어도 자동 예외로 두지 않고 이유를 남깁니다. ② 합계가 **가장 늦은 시점**의 값과 같음 — 물리적 마지막 행이 아니라 라벨을 해석해 정하고(역순 자료 포함), 라벨 형식이 섞이거나 해석할 수 없거나 가장 늦은 시점이 중복되면 예외를 두지 않고 이유를 남깁니다. '마지막 값과 같다'만으로는 예외로 두지 않으며(월별 건수 합계 20 = 2월 20 → 차단), 성격이 다른 열이 섞인 표는 근거가 없는 열을 그대로 검사합니다.
  - 소계의 그룹은 라벨 바로 왼쪽 글자를 먼저 씁니다 (`2026-08 | 서울 | 계` → `서울`).
  - 전체 합계(`전국`) 아래 그룹이 하나뿐이면(일부 지역만 담긴 자료) 전체 합계 검사를 생략합니다.
  - 병합 셀로 라벨이 `계`만 보이고 소계가 하위 행 **위에** 놓인 양식(`천안시 계` 다음 `동남구`·`서북구`)은, 그룹 소계이고 바로 아래 이어지는 행들이 한 그룹 전체(어느 글자 열의 같은 값을 가진 데이터 행 전부, 2행 이상)이며 그 합과 모든 숫자 열이 같을 때만 통과시킵니다. 전체 합계(`합계`·`전국`)에는 적용하지 않고, 비공개 값이 섞이면 적용하지 않습니다.

### 개인정보 탐지

- 업로드 시 모든 셀을 정규식으로 검사: 주민등록번호(생년월일 유효성 + 성별 1~8), 휴대전화(010/011/016/017/018/019), 이메일
- 원문은 저장·응답·로그하지 않고 **건수, 위치(시트/행/열), 마스킹 값**만 `source_files.pii_summary`에 저장합니다. 미리보기·매핑 샘플(LLM 입력 포함)도 마스킹됩니다.
- 발견 시 화면에 경고를 띄우고, 사용자가 확인(`POST /files/{id}/pii/acknowledge`)하기 전에는 검증 상태가 `pii_confirmation_required`입니다.

## 통합 전 사전 검토 (`/reviews`)

검증 섹션의 「사전 검토 열기」로 같은 검증 조건의 검토 세션을 만듭니다. 화면에서 가장 넓은 패널로 표시됩니다.

- 상단: 데이터 품질 점수(100점)와 한 줄 요약. 점수 = 100 − 차단 25 × 건수 − 남은 확인 필요 5 × 건수 − 경고 2 × 건수(최대 10), 차단이 있으면 최고 59점.
- 중앙: 보정 예정 항목을 `이전 값 → 이후 값` 한 줄로 보여주고, 펼치면 보정 근거 문장이 나옵니다.
  - 차단 오류(빨강): 합계 불일치·필수 기관 누락·기간 불일치 — 원본을 고쳐 다시 검사해야 함
  - 확인 필요(노랑, 승인/거부): 열 매핑 확인·미해결, 용어사전 확인 대상 이름, 개인정보 포함 파일
    - 열 매핑은 선택 상자에서 추천 후보(유사도 상위 3개)뿐 아니라 **다른 표준 항목 전체**에서 골라 승인할 수 있습니다.
  - 자동 적용(회색): 확정·자동 열 매핑, 별칭·약칭 이름 정규화, 숫자 문자열 변환, 병합 셀 채움, 2단 헤더 결합
  - 검증 경고(접힘, 참고): 전월 대비 이상치·공백 값·단위 추정
- 근거 문장: 규칙 판정은 고정 템플릿 문장(「규칙 문장」), **LLM 판정 항목만** LLM이 생성한 문장(「LLM 생성 문장」)을 씁니다.
- 승인/거부는 즉시 백엔드에 반영됩니다.
  - 열 매핑: 승인 → 고른 표준 항목으로 확정, 거부 → '해당 없음'으로 확정 (`mapping_decisions`)
  - 이름: 승인 → 고른 7자리 코드를 이번 검토의 선택값으로 저장
  - 개인정보: 승인 → 포함 확인 기록, 거부 → 이 파일을 이번 통합에서 제외
- 하단 「다음부터 이 형식 기억하기」: 선택하고 「검토 완료」하면 승인한 열 이름(학습 별칭)과 기관·지역 이름(용어사전 별칭)을 학습합니다. 선택하지 않으면 이번 검토에만 적용합니다.
- 「검토 완료」는 차단과 남은 확인 필요 항목이 없을 때만 가능하며 세션을 `ready`(통합 준비)로 바꿉니다.
- 다시 검사 세션 (`POST /reviews/{id}/recheck`): 같은 조건으로 다시 계산하되 이전 검토를 이어받습니다.
  - 같은 항목(종류·파일·시트·열·이전 값)의 승인/거부, 제외 파일, 「기억하기」 선택을 이어받고, 열 매핑 확정은 자동 적용으로 넘어옵니다.
  - `replace: {이전 파일 id: 고친 파일 id}`로 원본을 고쳐 다시 올린 파일로 바꿀 수 있습니다. 같은 형식이므로 열 매핑 확정을 복사하고, 개인정보 확인은 새 파일 기준으로 다시 받습니다.
  - 이전 세션은 `superseded`(대체됨)가 되어 더 바꿀 수 없습니다. 화면에 검사 이력(1차 → 2차 …)과 이전 검사 대비 변화(점수·차단·남은 확인 필요, 해결된 항목, 새로 생긴 항목)를 보여줍니다.
  - 「기억하기」로 완료하면 이번에 승인한 항목과 함께 이전 검사에서 확정해 이어받은 열 매핑도 학습합니다.
- API: `POST /reviews`, `GET /reviews/{id}`, `POST /reviews/{id}/items/{item_id}/decision`, `PATCH /reviews/{id}`(remember_format), `POST /reviews/{id}/complete`, `POST /reviews/{id}/recheck`

## 통합 결과 생성 (`POST /reviews/{id}/integrate`)

- **개인정보 정책**: 화면·API는 개인정보 형식을 가리지만, 결과 엑셀은 통합 결과 데이터라 원본 값을 그대로 담습니다. 개인정보가 탐지된 파일(머리글에만 있어도 탐지)은 사전 검토에서 포함을 **승인**해야 통합되고, **거부**한 파일은 결과 데이터·변경 내역에 들어가지 않습니다. 승인한 파일의 원문은 통합 데이터·열 머리글('해당 없음' 열 포함 시)·셀 메모·변경 내역 시트에 들어갈 수 있으며, 결과 화면이 내려받기 전에 이를 안내합니다. 결과 파일은 그 실행 기록을 볼 수 있는 사람(본인·최고 관리자)만 내려받을 수 있습니다.

검토가 끝난(검토 완료) 세션으로 결과 엑셀을 만듭니다. 검토 패널 하단의 「통합 결과 만들기 (엑셀)」로 실행하고 바로 내려받을 수 있습니다.

- 항상 새 파일: `data/outputs/통합결과_<실행번호>_<KST 시각>.xlsx` (임시 파일에 쓴 뒤 같은 이름이 없을 때만 옮기고 읽기 전용으로 둠). 원본은 읽기만 합니다.
- 시트 1 「통합 데이터」: 원본 파일·시트·행 + 표준 항목 열(기관·지역 열은 7자리 코드 열을 덧붙임). 제외 파일(개인정보 거부), 소계·합계·주석 행은 넣지 않고, '해당 없음' 열은 기본적으로 넣지 않습니다(아래 「표준 항목이 없는 열 포함」). 원본과 달라진 셀은 종류별 배경색과 메모(이전 값·근거)로 표시합니다.
- 시트 2 「변경 내역」: 원본 파일·시트·원본 행·통합 행·열·원본 열·이전 값·이후 값·종류·근거·확신도
- 시트 3 「처리 요약」: 처리 시각(KST), 검토·검증 번호, 입력 파일별 행 수, 통합 행 수, 변경 건수(종류별), 경고 건수, 통합하지 않은 열, 색 범례
- 시군구 열: 같은 시트에 시도 열이 있으면 시도를 뺀 이름(`강서구`), 없으면 정식명칭 그대로(`서울특별시 강서구`) 씁니다 (줄이면 `중구`·`강서구`처럼 구분이 사라지므로).
- `run_changes`: 통합 데이터의 **모든 셀을 파일에 적힌 값과 비교**해 달라진 셀(병합 셀 채움·숫자 변환·공백 정리·이름 정규화 등)을 빠짐없이 기록하고, 원본 열 이름 → 표준 항목 매핑도 기록합니다. 저장 전에 「색칠한 셀 = 셀 단위 기록」이 1:1인지 검사해, 어긋나면 결과 파일을 남기지 않고 실행을 실패로 기록합니다.
- 날짜 셀은 원본 형식 그대로 둡니다. 검토 패널의 자동 적용 예고와 결과의 변경 기록은 같은 기준입니다. CSV의 빈 문자열과 빈 칸은 같은 빈 값으로 보고 변경으로 기록하지 않습니다 (공백만 있던 칸 → 빈 칸은 '공백 정리').
- **표준 항목이 없는 열 포함** (선택): 「통합 결과 만들기」 위의 체크를 켜면 검토에서 '해당 없음'으로 정한 열도 원래 열 이름으로 결과에 넣습니다 (표준 항목 이름과 겹치면 `(원본 열)`을 붙임). 기본은 꺼짐(기존 동작). 자동화로 저장하면 이 선택도 저장되어 다음 실행에 그대로 적용됩니다. API: `POST /reviews/{id}/integrate` 본문 `{"include_unmapped": true}`
- API: `GET /runs`, `GET /runs/{id}`, `GET /runs/{id}/changes`, `GET /runs/{id}/download`

## 자동화와 실행 기록 (`/automations`, `runs`)

사이드바 메뉴 **홈**(대시보드 + 취합 작업) · **자동화** · **실행 기록**. 자동화는 사용자가 새 파일로 실행할 때만 동작합니다 (스케줄러·작업 큐 없음). 일반 사용자는 자기가 저장한 자동화와 자기 실행 기록만 봅니다.

- **자동화로 저장** (`POST /runs/{id}/automation`): 통합 결과를 만든 뒤 결과 아래에서 이름을 붙여 저장합니다. `automations` 테이블에 저장하는 것:
  - 열 매핑 규칙: 검토에서 승인했거나 자동 적용된 열 이름 → 표준 항목 (거부한 열은 '해당 없음'). 열 이름의 연도·단위 괄호·공백은 빼고 비교하므로 매월 바뀌는 '2026년' 같은 표기는 같은 열로 봅니다.
  - 이름 연결 규칙: 확인 필요였던 기관·지역 이름 → 승인한 7자리 코드 (거부 = 그대로 둠)
  - 검증 조건: 필수 기관, 기관 열, 전월 대비 증감 기준, 기준 기간(다음 실행 때 기본값)
  - 출력 형식: 결과 엑셀의 열 순서
  - 입력 파일은 저장하지 않습니다.
- **자동화 실행** (`POST /automations/{id}/run`): 자동화 메뉴에서 새 파일을 올리고 실행합니다. 저장된 규칙을 바로 적용해 해당 열·이름은 '자동 적용'으로 넘어가고, **저장된 규칙에 없는 새 열**(또는 처음 보는 이름, 개인정보 확인, 차단 오류)만 확인을 요청합니다.
  - 확인할 항목이 없으면 검토 완료 → 결과 엑셀까지 바로 만듭니다 (실행 기록: 완료).
  - 확인할 항목이 있으면 실행 기록을 '검토'로 남기고, 「확인할 항목 검토하기」로 검토 패널을 열어 이어서 처리합니다. 통합하면 같은 실행 기록이 '완료'로 바뀝니다.
  - 결과 열 순서는 저장된 출력 형식을 따르고, 새 열은 뒤에 붙습니다.
- **실행 기록** (`GET /runs`): `runs` 테이블 기준으로 시작 시각, 방식(직접 검토 / 자동화 이름), 입력 파일 수, 상태(완료 · 검토 · 실패), 소요 시간(시작 → 종료), 결과 파일 경로(`data/outputs/…`)와 내려받기를 최신 순으로 보여줍니다.
- 기타 API: `GET /automations`, `GET /automations/{id}`, `DELETE /automations/{id}`(자동화만 삭제, 실행 기록·결과 파일은 남김), `GET /runs?automation_id=`

## 계정과 권한 (`/auth/*`, `/users`, `/admin/*`)

모든 API는 로그인이 필요합니다 (예외: `/health`, `/auth/status`·`setup`·`signup`·`login`·`logout`). 화면 메뉴는 역할에 맞는 것만 보이고, 서버도 같은 기준으로 막습니다 (권한 없음 403, 남의 기록은 404). 역할은 두 가지이고, 계정 상태는 역할과 따로 관리합니다.

| 역할 | 화면 표시 | 할 수 있는 일 |
| --- | --- | --- |
| `owner` | 최고 관리자(소유자) | 가입 승인·사용자 관리(`/moajwoAdmin`), 전체 이용 현황, 서비스 설정, 공통 사전 관리·승격 심사, 전체 사용자 기록 **조회(읽기 전용)** |
| `user` | 일반 사용자 | 자기 파일·검토·통합·자동화·**자기 실행 기록만**. 관리 메뉴 없음 |

예전 중간 관리자(`admin`)는 마이그레이션 0016에서 일반 사용자로 바뀌고 기존 세션이 끝납니다. 신규 계정 생성·역할 변경 API는 `admin`·`owner`를 받지 않습니다 (최고 관리자 추가·소유권 이관은 없음).

| 계정 상태 | 의미 | 업무 기능 | 로그인할 때 |
| --- | --- | --- | --- |
| 승인 대기 (`pending`) | 가입 신청 후 심사 전 | 불가 | 비밀번호가 맞으면 "최고 관리자의 승인 후 로그인할 수 있습니다" |
| 이용 중 (`active`) | 최고 관리자가 승인 | 가능 | 로그인 |
| 가입 반려 (`rejected`) | 가입 신청이 반려됨 | 불가 | 비밀번호가 맞으면 반려 안내 |
| 이용 중지 (`suspended`) | 쓰던 계정의 접근 중단 | 불가 | 비밀번호가 맞으면 중지 안내 |

- 아이디·비밀번호가 틀리면 상태와 관계없이 같은 오류만 보여 줍니다 (계정 존재·상태를 알 수 없음). 상태 안내 때도 세션은 만들지 않습니다.
- 모든 업무 API가 요청마다 `status = active`이면서 `is_active`인지 확인합니다 (메뉴 숨김이 아니라 서버에서 막음). `is_active`는 상태와 항상 같게 유지해 이전 코드도 승인 대기·반려 계정을 막습니다.
- 상태 전이는 승인(대기→이용 중)·반려(대기→반려)·이용 중지(이용 중→중지)·재개(중지→이용 중)만 허용합니다. 조건부 갱신이라 중복 클릭·동시 요청에도 한 번만 반영되고, 나머지는 409와 함께 관리 이력에 '반영 안 됨'으로 남습니다. 반려한 신청은 다시 승인할 수 없습니다 (같은 아이디로 다시 가입도 불가). 최고 관리자 계정은 이용 중지·역할 변경·비밀번호 초기화 대상이 아닙니다 (자기 비밀번호는 「내 계정」).
- 가입 신청에 역할·상태·활성 여부 같은 필드를 보내면 422로 거부합니다 (서버가 일반 사용자·승인 대기로 정함). 아이디 중복은 DB 유일 조건으로도 막습니다 (동시 가입 중 하나만 성공).
- 반려·이용 중지·비밀번호 초기화·본인 비밀번호 변경은 그 계정의 세션을 모두 끝냅니다 (남은 쿠키로도 업무 API 401). 동시 요청에서도 유지되도록 **인증 버전**(`users.auth_version`)을 씁니다: 이 작업들은 같은 UPDATE에서 버전을 올리고, 세션은 발급 시점의 버전과 같을 때만 유효합니다. 로그인은 비밀번호 확인 때 읽은 버전·이용 중 상태를 조건으로 한 UPDATE와 세션 저장을 한 트랜잭션에서 하므로, 확인 직후 초기화·중지가 끼어들면 세션을 만들지 않습니다. 버전은 내려가지 않아 이용 재개 후에도 이전 쿠키가 되살아나지 않고 새 로그인이 필요합니다.
- **관리 이력**(`account_events`): 가입 신청·승인·반려·이용 중지·재개·비밀번호 초기화·계정 추가·역할 전환을 작업자·대상·시각·변경 전후 상태·사유·결과로 남깁니다. 계정 변경과 같은 트랜잭션입니다. 비밀번호·쿠키·토큰은 기록하지 않습니다.

### 관리자 화면 (`/moajwoAdmin`, 최고 관리자만)

| 주소 | 내용 |
| --- | --- |
| `/moajwoAdmin` | 관리 현황: 승인 대기·이용 중·이용 중지 사용자 수(지금 시점), 선택 기간의 업로드 파일 수, 통합 실행·완료·실패·검토 대기 건수. 기간은 KST 시작일 00:00 ~ 종료일 24:00 (기본: 이번 달), 실행은 홈 대시보드와 같은 시작 시각 기준. 계정 상태와 관계없이 모든 기록을 세고(이용 중지된 검증용 계정 기록도 포함), 그중 이용 중이 아닌 계정·계정 도입 전 기록 수를 따로 보여 줍니다. 절약 시간 같은 추정치는 표시하지 않습니다. |
| `/moajwoAdmin/users` | 사용자·가입 신청: 아이디·표시 이름 검색, 상태별 필터, 가입일·최근 로그인·**최근 업무 활동**(업로드·검증·검토·통합의 마지막 시각, 로그인과 별개)·현재 상태, 가입 승인·반려, 이용 중지·재개(사유 기록), 비밀번호 초기화, 계정 직접 추가 |
| `/moajwoAdmin/audit` | 관리 이력 (최신 200건) |

- 비로그인으로 열면 로그인 화면, 일반 사용자는 403 화면이 나오고 관련 API도 403입니다. 예전 주소 `/users`는 `/moajwoAdmin/users`로 이동합니다.
- API: `GET /admin/overview?start=&end=`, `GET /admin/audit`, `GET /users?q=&status=`, `POST /users`(일반 사용자, `status`: `active`|`pending` 필수), `PATCH /users/{id}`(표시 이름만), `POST /users/{id}/approve|reject|suspend|resume`(`reason` 선택), `POST /users/{id}/password`

- **결과 데이터는 누구도 직접 수정할 수 없습니다** (최고 관리자 포함): 실행 기록·변경 기록(`run_changes`)·결과 파일을 바꾸는 API가 없고(`PUT/PATCH/DELETE /runs/{id}` → 405), 결과 파일은 읽기 전용입니다. 남의 검토를 대신 승인·완료·통합할 수도 없습니다 (조회만). 남의 파일로 **자기** 검토를 만들어도(조회용) 그 파일의 매핑 확정·개인정보 확인은 파일을 올린 사람만 할 수 있어 403이 되고, 재검사의 파일 교체·자동화 실행도 남의 파일에는 확정을 기록하지 않습니다. 검토 응답의 항목별 `can_change`로 화면이 이런 항목의 승인·거부 버튼을 끄고 「조회 전용이며 파일을 올린 사용자만 변경할 수 있습니다」를 안내합니다 (여러 사람의 파일이 섞인 검토는 항목별로 판단, 결정이 거부되면 최신 상태로 다시 불러옴).
- 비밀번호: 표준 라이브러리 scrypt + salt로 저장. 로그인: HttpOnly·SameSite=Strict 쿠키(12시간), DB에는 토큰 해시만 저장. 5번 연속 실패하면 5분 잠금. 비밀번호 변경·초기화·반려·이용 중지 시 그 계정의 로그인을 끊습니다. HTTPS로 운영하면 `MOAJWO_COOKIE_SECURE=1`.
- 계정 도입 전에 만든 기록(소유자 없음)은 최고 관리자만 봅니다.
- API: `GET /auth/status`(최초 설정 필요 여부 + 로그인한 사용자), `POST /auth/setup`(최초 설정 전에만, 최고 관리자), `POST /auth/signup`(최초 설정 후, 승인 대기·세션 없음), `POST /auth/login`·`logout`, `GET /auth/me`, `POST /auth/password`

## 매핑 규칙 승격 (`/admin/promotions`, `standard_terms`)

1. 사용자가 열 매핑을 승인하면(검토 패널의 승인, 매핑 화면의 확정) `mapping_approvals`에 (열 이름, 표준 항목, 사용자)로 1건 기록합니다. 같은 사용자의 반복 승인은 1건입니다.
2. **서로 다른 사용자 3명 이상**이 같은 매핑을 승인하면 「승격 심사」 대기열(`promotion_candidates`)에 올라갑니다. 기본 표준 사전에 이미 있는 이름·헤더 없는 열은 제외합니다.
3. 최고 관리자가 **승인하면 전사 표준 사전(`standard_terms`)에 반영**되어 모든 사용자의 매핑 1단계에 자동 적용됩니다 (근거: "전사 표준 사전과 일치"). 반려한 후보는 다시 올라오지 않습니다. 「사전 관리」에서 반영된 이름을 뺄 수 있습니다 (이미 만든 결과는 그대로).

## 홈 대시보드 (`GET /dashboard`)

홈 화면 맨 위에 표시합니다. 일반 사용자는 자기 기록, 최고 관리자는 전체 기준입니다.

| 지표 | 계산 |
| --- | --- |
| 이번 달 실행 횟수 | 이번 달(KST)에 시작한 실행 기록 수 (완료 수 함께 표시) |
| 누적 절약 시간 | 완료된 실행마다 `max(0, 수동 기준 소요 시간 − 실제 처리 시간)`의 합. 기준 시간은 소유자가 「설정」에서 정함(자동화별로 다르게 정할 수 있음). 정하지 않으면 계산하지 않음. 실제 처리 시간 = 실행 기록의 시작 → 종료 |
| 검증한 행 수 | 검증(검토 포함)을 한 번 이상 거친 파일들의 데이터 행 수 (같은 파일, 또는 내용(sha256)이 같아 다시 올린 파일은 한 번만) |
| 통합 전 발견한 오류 건수 | 검토에서 찾은 차단 오류 + 검증 경고. 다시 검사에서 이전 검사와 같은 항목은 다시 세지 않음 |

- 기준 시간은 현재 설정값으로 다시 계산합니다 (설정을 바꾸면 지난 실행도 새 기준으로 계산).
- 사이드바의 **데이터 연결 (DB·Kibana)** 은 준비 중이라 누를 수 없습니다.
- 사이드바 맨 위에 로그인한 계정과 **역할 뱃지**([일반]·[최고 관리자])를 표시합니다. 권한 없는 메뉴는 그리지 않고 자물쇠 안내만 보이며, 주소로 직접 들어오면 403 화면에 필요한 권한과 내 권한을 보여줍니다.

## LLM 제공자 설정 (`/settings/llm`, 소유자)

열 매핑 3단계(사전·유사도로 정하지 못한 열)의 판정에 쓸 LLM을 고릅니다. 설정은 `app_settings`(key `llm_provider`)에 저장되고 저장 즉시 적용됩니다.

| 모드 | 내용 |
| --- | --- |
| 로컬 내장형 (Ollama) — **기본값** | 기존과 같음. 자료가 밖으로 나가지 않음. 모델 이름을 비우면 `OLLAMA_LLM_MODEL`(qwen2.5:7b) |
| 외부 API · OpenAI | `/v1/chat/completions` + JSON 스키마 응답. API Key·모델 이름 필수, 주소는 https만 |
| 외부 API · Anthropic | `/v1/messages` + 도구 강제 호출로 스키마에 맞는 JSON. API Key 필수, 모델은 비우면 `claude-haiku-4-5-20251001` |
| Custom Endpoint | OpenAI 호환 `/chat/completions` (사내 vLLM·LM Studio 등). URL·모델 필수, 키 선택 |

- 외부 모드에서 보내는 내용: 판정이 필요한 열의 이름, 그 열의 샘플 값 최대 5개(주민번호·전화·이메일 패턴은 마스킹된 값), 표준 항목 목록. 원본 파일 전체·결과 파일은 보내지 않습니다. 화면에서 선택할 때 이 내용을 안내합니다.
- 임베딩(bge-m3 유사도)은 모드와 관계없이 항상 로컬 Ollama입니다.
- API Key는 서버 DB에만 저장하고 응답·화면·로그에 내보내지 않습니다(끝 4자리만 표시, 오류 메시지에서도 가림). 같은 제공자에서 키 칸을 비워 저장하면 기존 키를 유지하고, 로컬로 되돌리면 키를 지웁니다. DB 파일 자체는 암호화하지 않으므로 서버 접근 권한을 관리하세요.
- 「연결 테스트」는 저장된 설정으로 짧은 확인 요청 하나만 보냅니다 (자료 내용 없음).
- API: `GET|PUT /settings/llm`, `POST /settings/llm/test` (소유자만, 그 외 403)

## 화면 피드백

- **사전 검토 패널**: 본문 영역 전체 너비를 쓰고, 항목은 한 줄(종류 | 이전 → 이후 | 위치 | 결정)로 압축해 보여줍니다. 근거는 마우스를 올리면 툴팁으로 요약이 보이고, 누르면 아코디언으로 펼쳐집니다. 긴 근거(LLM 문장)는 두 줄까지만 보이고 「전체 보기」 창에서 전부 읽습니다.
- **진행 표시**: 업로드(실제 전송률 → 파일 파싱 → 개인정보 확인), 열 매핑 분석(사전 비교 → AI 매핑), 사전 검토·자동화 실행(파일 파싱 → AI 매핑 → 데이터 검증 → 항목 정리) 동안 진행 막대와 단계 문구를 보여줍니다. 서버는 한 번의 요청으로 처리하므로 업로드 전송률 외의 단계와 막대는 예상 시간 기준의 추정치이며, 응답 전에는 95%를 넘지 않습니다. 업로드 중에는 처리 중인 파일 자리에 스켈레톤을 보여줍니다.

## 용어사전 (기관·자치단체 이름, `/glossary/*`)

기관·자치단체 이름을 **7자리 코드**로 해석해, 약칭·표기 차이·조직 개편이 있어도 같은 대상으로 비교합니다. 현행 기관끼리 7자리 코드가 겹치지 않으므로 항목은 이 코드 하나로 식별하고, 자치단체는 **시도코드(2자리)·시군구코드(3자리)**를 속성으로 둡니다. 용어사전은 **사용자가 업로드해 관리**하며, 처음에는 중앙부처 6개·자치단체 8개와 별칭 1개(`행안부`)만 **예시**로 들어 있습니다 (마이그레이션 0005).

- **기본 광역 항목** (마이그레이션 0011): 현행 광역 16개(2026-07 광주·전남 통합으로 17 → 16)와 옛 자료용 폐지 광역 4개(광주광역시·전라남도 ~2026-06-30, 강원도 ~2023-06-10, 전라북도 ~2024-01-17)를 넣어, 사전을 올리지 않아도 `서울`·`세종`·`충북` 같은 약칭을 해석합니다. 7자리 코드·존속 기간은 행정안전부 행정표준코드 기관코드 전체자료(2026-10-02) 기준이며, 같은 코드나 같은 이름의 현행 항목이 이미 있으면 넣지 않습니다.
- **행정구역 개편 기본 항목·별칭** (마이그레이션 0012): 2018년 이후 폐지·신설된 기초자치단체 129개(인천 남구→미추홀구, 강원·전북 특별자치도 전환, 경북 군위군→대구, 인천 중구·동구·서구→제물포구·영종구·서해구·검단구, 광주광역시·전라남도 시군구→전남광주통합특별시)를 기본 항목으로 넣고, 폐지 항목의 정식명칭과 약칭(`인천 동구`, `광주 동구`, `전남 목포시`)을 승계 항목에 잇는 **기본 별칭**을 개편 시행일부터 유효하게 넣습니다. 기준일이 개편 전이면 옛 항목, 개편 후면 승계 항목으로 해석되고, 나뉜 구역(`인천 중구` → 제물포구·영종구)은 후보를 모두 보여주는 모호로 둡니다. `광주`·`전남`은 개편 전 자료의 이름이라 광주광역시·전라남도(2026-06-30까지)로 해석합니다. 기본 별칭은 내보내기 CSV에 넣지 않습니다(다시 올리면 유효기간이 사라지므로).
- **일반구 기본 항목** (마이그레이션 0013): 행정동 코드표의 현존 일반구 39개(고양시 덕양구, 성남시 분당구, 청주시 흥덕구, 천안시 서북구, 전주시 완산구, 포항시 남구, 창원시 마산합포구 등)와 2024-01-17까지 쓰인 전라북도 전주시 완산구·덕진구를 유형 '일반구'로 넣습니다 (7자리 코드: 기관코드 전체자료의 하부행정기구 코드). `경기 고양시 덕양구`, `고양시 덕양구`처럼 해석합니다. 부천시 3개 구는 2024-01-01, 화성시 4개 구는 2026-02-01부터 유효합니다.

- 관리: 사이드바 「사전 관리」(최고 관리자). 일반 사용자는 조회·해석(검증)만 하고, 별칭 등록·업로드·삭제는 할 수 없습니다. '이 형식 기억하기'로 기관·지역 이름을 사전에 학습하는 것도 최고 관리자만 합니다 (일반 사용자는 검토에서 이번 통합에만 연결).
- 업로드: 「사전 관리」의 「용어사전 파일 업로드」 또는 `POST /glossary/import` (CSV·xlsx·xls, 10MB). 양식은 `GET /glossary/template.csv`, 현재 사전은 `GET /glossary/export.csv`(다시 올릴 수 있는 형식).

  | --- | --- |

  - 같은 코드는 갱신, 새 코드는 추가. **오류가 한 행이라도 있으면 아무것도 반영하지 않고** 오류 행을 모두 알려줍니다.

- 해석 기준일: 기준 기간의 말일. 기준 기간을 넣지 않으면 **모든 파일**의 대표 기간(기간 검사와 같은 근거, 없으면 파일명의 8자리 날짜 `_20240331`)을 확인할 수 있고 모두 같을 때만 그 기간으로 해석하고 참고에 남깁니다. 기간을 모르는 파일이 있거나, 파일 안에서 기간이 동률로 갈리거나, 파일끼리 다르면 정하지 않고 이유를 참고에 남긴 뒤 오늘 기준으로 해석합니다. 기준일이 없을 때(오늘 기준)도 항목·별칭의 시작일과 종료일을 모두 검사해, 아직 시작하지 않은 항목은 이름·별칭 어느 경로로도 확정하지 않고 안내와 함께 후보로만 보여 줍니다 (폐지된 항목은 옛 자료 비교용으로 해석하되 안내를 붙이고 통합에서 자동으로 바꾸지 않음) (검토가 정한 기간을 통합도 그대로 씀). 파일명 날짜는 기간 검사에는 쓰지 않습니다.
- 검증 연동: 필수 기관 누락과 전월 대비 비교는 7자리 코드로 비교합니다. 사전에 없거나 모호하거나 기준일에 유효하지 않은 이름은 **용어사전 확인 대상**으로 따로 보여주며(상태에 영향 없음), 화면에서 후보를 골라 바로 별칭으로 등록할 수 있습니다.
