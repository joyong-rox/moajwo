# 공통 key로 연결하기 (`/keyjoin`)

여러 파일(또는 한 파일의 여러 시트)에 흩어진 **같은 사용자**를 key(사번·사용자번호·ID 등)로 연결해 **사용자별 한 행**을 만들고,
입력마다 고른 열만 결과에 넣습니다. 열 매핑·검토를 거치지 않으며, 기존의 하나의 통합표·파일별 시트 묶기·통계 요약은 그대로입니다.

- 서버: `backend/app/keyjoin.py`(판정·결과 파일), `backend/app/keyjoin_api.py`(`POST /keyjoin/plan`, `POST /keyjoin/run`)
- 실행 기록·내려받기: 기존 `GET /runs`, `GET /runs/{id}`, `GET /runs/{id}/download` (실행 기록에 **key 취합**으로 표시)
- 시트·열 목록: 기존 `GET /files/{id}/preview?sheet_id=sN` (가린 이름과 `sheet_id`·`column_id`)
- 시험: `backend/tests/test_keyjoin.py`(6-1 기대값·6-2 경계), `test_keyjoin_keys.py`(key 정규형), `test_run_completion.py`·
  `test_run_recovery.py`(완료 경계·프로세스 종료)

## 흐름 (7단계)

1. **파일·시트 선택** — 입력 = (파일, 시트) 한 쌍. 같은 파일의 다른 시트는 다른 입력입니다. 시트가 여러 개면 직접 고릅니다.
2. **key 열 지정** — 입력마다 key 열을 고릅니다. 이름이 달라도 됩니다(`사번`·`사용자번호`·`사용자ID`). 복합 key는 열을 순서대로
   여러 개 고르며, 모든 입력이 같은 개수여야 합니다(i번째끼리 대응).
3. **가져올 열 선택** — 입력마다 결과에 넣을 열과 결과 이름을 정합니다(비우면 원본 열 이름). 표준 항목 등록 여부와 무관하게 어떤 열이든
   고를 수 있습니다. key 열은 결과에 이미 들어갑니다.
4. **포함할 사용자 범위** — 기준 파일의 사용자만(기본) · 모든 파일의 사용자 · 모든 파일의 공통 사용자. 기준 입력은 항상 정합니다.
5. **연결 확인** (`POST /keyjoin/plan`, 읽기 전용) — 입력을 다시 읽어 결과 열 이름·행 수·연결/미연결 수·문제·경고·미리보기(앞 20행)를
   보여 줍니다. 파일을 만들지 않습니다. 설정을 바꾸면 다시 확인해야 합니다.
6. **생성** (`POST /keyjoin/run`) — 확인한 구성(`basis`)과 같을 때만 만듭니다. 바뀌었으면 409로 거절하고 아무것도 남기지 않습니다.
7. **실행 기록·다운로드** — 실행 기록에 **key 취합**(범위 포함)으로 남고, 결과 파일을 내려받습니다.

선택은 파일 ID·`sheet_id`·`column_id`로만 보냅니다(가린 표시 이름은 식별자가 아닙니다). 파일·시트를 요청에서 빼면 그 key·열 설정도 함께
빠집니다.

## key 규칙 (정확 일치)

| 입력 칸 | key | 설명 |
|---|---|---|
| 글자 `001`·`A-17`·`kim@…` | 그대로 | 앞자리 0·긴 자릿수·대소문자·앞뒤 공백을 **보존**합니다. `' 001'`과 `'001'`, `'abc'`와 `'ABC'`는 다른 사용자입니다 |
| 정수 칸 `123` | `'123'` | 10진 문자열로 바꿔 글자 `'123'`과 **연결**합니다. `'00123'`과는 **다릅니다** (표시 형식의 0은 만들지 않음) |
| xls 숫자 칸 `123.0` | `'123'` | xls는 숫자가 모두 실수라, 정수 값이면 정수와 같은 경로입니다 |
| 소수·NaN·참거짓·날짜·시각 | 차단 | 자동으로 해석하지 않습니다 — 문자형(텍스트) 식별자로 저장해 다시 올리세요 (`KEYJOIN_KEY_TYPE`) |
| 16자리 이상 숫자 칸, xls 2^53 이상 | 차단 | 자릿수 보존을 확인할 수 없습니다 — 텍스트로 저장한 자료를 올리세요 (`KEYJOIN_KEY_PRECISION`) |
| 병합으로 채워진 칸 | 차단 | 위 행의 값을 복사해 연결하지 않습니다 — 행마다 key를 적으세요 (`KEYJOIN_KEY_FILLED`) |
| 빈 칸·공백만 / `-`·`x`·`N/A` 등 결측 표기 | 차단 | 빈 값끼리 연결하지 않습니다 (`KEYJOIN_KEY_EMPTY`·`KEYJOIN_KEY_MISSING_MARK`) |
| 복합 key의 일부가 빈 값 | 차단 | 일부만으로 연결하지 않습니다 (`KEYJOIN_KEY_PARTIAL`) |

- key는 파서가 숫자로 바꾸기 **전의 값**으로 만듭니다. 다른 기능(미리보기·통합·분석)의 숫자 해석은 바뀌지 않습니다.
- 복합 key는 구분자로 이어 붙이지 않고 **튜플**로 비교합니다 (`('a|b','c')`와 `('a','b|c')`는 다름). 열 순서를 바꾸면 다른 key입니다.
- **한 입력 안에서 같은 key가 두 번** 나오면 만들지 않습니다(`KEYJOIN_KEY_DUPLICATE` — 묶음 수·행 수·처음 5행 번호). 합치거나 고르지 않습니다.
  입력 사이의 같은 key는 정상 연결입니다(통계의 중복 의심으로 거절하지 않음).
- 소계·합계·주석으로 분류된 행은 연결하지 않고 경고로 행 번호를 알립니다(`KEYJOIN_NONDATA_ROWS_SKIPPED`). `'계'`·`'합계'`처럼 보이는 값의
  행도 여기에 들어가니 행 번호를 확인하세요.
- 공백 제거·대소문자 통일·유사 일치·중복 합산·첫 행 선택 옵션은 첫 버전에 없습니다. 앞뒤 공백만 다른 key(`KEYJOIN_WHITESPACE_VARIANTS`),
  정수 칸과 글자 key의 연결 수(`KEYJOIN_INT_TEXT_LINK`), 한 key 열의 정수·글자 섞임(`KEYJOIN_MIXED_KEY_KINDS`)은 경고로 알립니다.

## 범위와 출력 순서

| 범위 | 결과 행 | 순서 |
|---|---|---|
| `base` 기준 파일의 사용자만 (기본) | 기준 입력의 key | 기준 입력의 행 순서. 다른 입력에 없으면 그 입력의 열은 빈 칸 |
| `all` 모든 파일의 사용자 | 모든 입력 key의 합집합 | 기준 입력 순서 → 나머지 입력 순(요청 순)·행 순서로 처음 나온 key |
| `common` 모든 파일의 공통 사용자 | 모든 입력에 있는 key | 기준 입력 순서. 빠지는 사용자 수를 경고로 알림(`KEYJOIN_EXCLUDED`). 0행이면 `KEYJOIN_NO_COMMON`으로 생성하지 않음 |

## 결과 파일 (`data/outputs/key연결_<실행번호>_<KST 시각>.xlsx`)

- 시트 「연결 결과」: key 열(들) + 고른 열. **key 칸은 항상 글자 형식**입니다(Excel이 '숫자가 텍스트로 저장됨'을 표시할 수 있음 —
  선행 0·자릿수 보존이 우선). 미연결·원본 빈 칸은 **빈 칸**(0 아님), 실제 0은 0. 16자리 이상 정수 값은 글자로, 결과값이 저장되지 않은
  수식 칸은 빈 칸 + 메모, `=`로 시작하는 글자는 수식이 아니라 글자입니다. 선택하지 않은 열은 **어느 시트에도** 넣지 않습니다.
- 같은 이름의 열이 둘 이상이면 뒤 것에 `(입력 n · #파일번호)`를 붙여 구분합니다(값을 덮거나 합치지 않음). 사용자가 적은 결과 이름끼리 같거나
  key 이름과 같으면 거절합니다(`KEYJOIN_OUT_NAME_DUPLICATE`).
- 시트 「출처」: 결과 행 번호와 입력별 **원본 행 번호**(미연결은 빈 칸). 시트 「연결 요약」: 실행 번호·정책·basis·범위·기준 입력·입력 표(가린 이름)·
  행/연결 수·경고. 두 시트에 key 원문·셀 값은 없습니다.

## 거절과 안내

- 요청 형식(422, 문구 끝에 `[코드]`): 입력 2개 미만·같은 입력 두 번·key 개수 불일치·같은 열 두 번·key 열을 가져올 열로 고름·없는 시트/열·
  기준 입력이 목록에 없음·결과 이름이 비었거나 255자를 넘거나 쓸 수 없는 글자(NUL 등)·결과 열 200개 초과.
- 연결 확인의 **차단**(`ready: false` → 생성 409 `KEYJOIN_NOT_READY`): 위 key 규칙의 차단, 다른 사용자의 파일(최고 관리자 조회만 —
  `KEYJOIN_FILE_NOT_OWN`), 개인정보 포함 확인 전(`KEYJOIN_PII_ACK_REQUIRED`, 기존 `POST /files/{id}/pii/acknowledge`), 읽은 시트 없음,
  쓸 수 없는 글자가 든 값·이름(위치만 알림), 공통 사용자 없음, 기준 입력 데이터 행 0, 한도 초과.
- 생성 거절(409): 확인 뒤 변경(`KEYJOIN_BASIS_CHANGED` — 파일 내용·시트·열·key·범위·이름·개인정보 확인 상태·한도 중 하나라도),
  같은 요청 번호에 다른 설정(`KEYJOIN_REQUEST_MISMATCH`), 실패한 요청 번호의 재사용(`KEYJOIN_REQUEST_USED`), 만드는 중 실패(`KEYJOIN_FAILED`,
  예외 종류와 실행 번호만). 거절이면 실행 기록·결과·임시 파일·학습·확정을 남기지 않습니다.
- 다른 결과를 만드는 중이면 503 `output_busy`(기존 결과 만들기 차례), 결과 파일이 지워졌으면 내려받기 410(기존).
- 문구에는 **위치(입력 번호·파일 번호·시트 순번·열 문자·행 번호)·개수·코드만** 넣고 key 원문·가린 key·해시는 넣지 않습니다.
  가린 뒤 같아지는 key(이메일·전화)는 합치지 않고 미리보기에 `(가림 구분 n)`을 붙입니다. 결과 파일에는 원래 key가 들어갑니다(개인정보가 탐지된
  파일은 포함 확인 뒤 — 기존 정책).

## 중복 제출 (같은 생성 요청을 두 번 보냄)

화면은 생성 요청마다 `request_id`(32자리 hex)를 만들어 보냅니다. 서버는 이 사용자의 최근 50건에서 같은 번호의 key 연결 실행을 찾아,
있고(running/done/check) 같은 `basis`면 **새로 만들지 않고 그 실행을 200**으로 돌려줍니다(새로 만들면 201). 같은 번호에 다른 설정이면
409 `KEYJOIN_REQUEST_MISMATCH`, 실패로 끝난 번호를 다시 쓰면 409 `KEYJOIN_REQUEST_USED`(새 번호로 다시). 같은 프로세스의 동시 둘째 요청은
503 `output_busy`입니다. 제한: 최근 50건 밖의 번호는 찾지 못하고, 서버 프로세스를 여럿 띄우는 구성에서는 두 프로세스가 동시에 '없음'을 읽는
경합이 남습니다(그 구성을 택하면 `runs`에 요청 번호 고유 색인이 필요 — 지금 이미지는 프로세스 1개).

## 한도 (코드 상수 — `backend/app/keyjoin.py`, 측정 뒤 조정)

| 항목 | 값 |
|---|---|
| 입력 수 / 복합 key 열 수 / 입력당 가져올 열 / 결과 열 | 20 / 5 / 50 / 200 |
| 모든 입력의 데이터 행 합계 | 300,000 (`KEYJOIN_TOO_MANY_ROWS`) |
| 결과 칸 | 결과 행 × (key 열 + 가져올 열 + 1 + 입력 수) + 요약 고정분, **출처 시트 포함**. 여기에 key 인덱스 칸 × `INDEX_WEIGHT`(1.0)를 더해 기존 `MOAJWO_MAX_OUTPUT_CELLS` 안이어야 함 (`KEYJOIN_TOO_MANY_CELLS`) |
| 결과 글자 | 선택한 열·key 열의 글자 수 추정 × `TEXT_WEIGHT`(2) ≤ 기존 `MOAJWO_MAX_OUTPUT_TEXT_CHARS` (`KEYJOIN_TOO_MANY_CHARS`) |
| 엑셀 행 | 결과 행 + 1 ≤ 1,048,576 |
| 미리보기 | 앞 200개 key 가운데 20행 (`preview.total`은 정확한 전체 행 수) |

한도는 파일을 읽기 전에 시트별 개수로 먼저 보고(넘으면 읽지 않음), 읽은 뒤 정확한 값으로 다시 셉니다. 측정 근거와 환경별 권장값은
[MEMORY.md](MEMORY.md)의 '공통 key 연결' 절에 적습니다(CI 측정 K1~K3 뒤 상수 조정).

## 실행 기록 표시

`runs.summary.mode == "keyjoin"`(시작 요약부터 — 실패 기록도 같음), `mode_label "공통 key 연결"`, `scope`, `request_id`, `basis`, `inputs`(시작 요약은
입력 수, 완료 요약은 입력 목록 — `input_count`에 수가 따로 있음), 완료 요약에 `result{rows, columns, key_columns}`, `counts{union, intersection,
excluded}`, `header`(가림), `sheet_order`, `warnings`. 화면은 방식 열에 **key 취합**과 범위를, 결과 열에 "연결: 입력 n개 · 결과 m행 · 열 k개"를 보입니다.
과거 기록 조회·다운로드는 기존 그대로이며, 담당 프로세스가 끝난 실행의 정리(`app/recovery.py`)도 같은 규칙(실패로 두면 시작 요약만 남음)입니다.
