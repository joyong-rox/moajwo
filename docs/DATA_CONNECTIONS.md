# 데이터 연결 (DB·Kibana) — 설계 초안

> **상태: 초안 (2026-11-06) — 구현 전.** 이 문서는 설계만 담습니다. 코드·DB·이미지는 아직 바꾸지 않았습니다.
> 소유자가 [2장 확인 질문](#2-구현-전에-소유자에게-확인할-것)에 답하고 이 설계를 승인한 다음 회차에 구현합니다.
> 접속 주소·호스트 이름·포트·계정·비밀값은 이 저장소에 적지 않습니다 (공개 저장소). 이 PC를 점검한 결과는 저장소 밖 회차 기록에 둡니다.

## 1. 목표와 범위

**목표:** 사내 DB나 Kibana(Elasticsearch)에 저장된 통계를 사람이 내려받아 올리지 않고, 저장해 둔 조회로 읽어 **원본 파일처럼 등록**합니다.
등록한 뒤에는 지금 업로드한 파일과 같은 흐름(개인정보 탐지 → 매핑 → 검증·검토 → 통합, 또는 공통 key 연결)을 그대로 탑니다.
데일리 통계처럼 같은 조회를 날짜만 바꿔 되풀이하는 일을 줄이는 것이 목적입니다.

**이번 설계에 넣는 것**
- 연결 등록·연결 시험 (DB 한 종류 이상 + Elasticsearch/Kibana)
- 저장한 조회: 정의, 미리보기(최대 N행), 실행 → 원본 파일 등록
- 기준일 변수(어제·지난달 등)
- 읽기 전용 보장, 비밀값 보관, 접속 범위 제한
- DB 변경(0025 예정), 드라이버·이미지 영향, 시험 계획, 화면 초안

**넣지 않는 것**
- 정기 실행(매일 자동 실행). 나중에 붙일 수 있게 실행 함수만 그렇게 나눕니다 (7-3).
- 원천 DB·인덱스에 쓰기: 어떤 경로로도 하지 않습니다.
- 외부 인터넷 서비스로의 연결: 폐쇄망 원칙은 그대로입니다 (5장).
- 작업 큐·별도 워커: 프로젝트 규칙상 Celery·Redis·VectorDB를 쓰지 않습니다.

## 3. 흐름

```
[데이터 연결] ─ 연결 등록(소유자) ─ 연결 시험(읽기 1회, 쓰기 없음)
      │
      └─ 저장한 조회: 정의(SQL 또는 ES 조회 + 기준일 변수) ─ 미리보기(최대 N행, 파일 안 만듦)
                │
                └─ 실행(기준일 지정) ─ 결과 스냅숏(xlsx) 저장 ─ 원본 파일로 등록 ─ 홈 파일 목록
                                                           │
                                     (여기부터 지금과 같음) 개인정보 탐지 → 매핑 → 검증·검토 → 통합 / 공통 key 연결
```

- 사이드바의 '데이터 연결 (DB·Kibana)' 자리(지금은 '준비 중'으로 누를 수 없음)를 이 화면으로 씁니다.
- **실행 한 번 = 원본 파일 하나**입니다. 같은 조회를 다시 실행하면 새 파일이 생기고, 예전 파일을 덮어쓰지 않습니다 (원본 읽기 전용 원칙).
- 등록한 파일에는 출처를 붙입니다: 연결 이름 · 조회 이름 · 조회 정의 판 · 기준일 · 실행 시각 · 행 수 · sha256. 파일 목록과 실행 기록에서 보입니다.

## 4. 읽기 전용 보장

**1차 방어는 읽기 전용 계정**입니다 (Q4). 앱은 그 위에 다음을 겹칩니다. 앱 쪽 조치만으로 쓰기를 막는다고 가정하지 않습니다.

### 4-1. DB 공통

- **문장 검사 (저장할 때와 실행할 때 모두):** 한 문장만 허용합니다(끝의 세미콜론 하나만 허용, 문장 사이 세미콜론 거부). 주석을 뺀 첫 낱말이 `SELECT` 또는 `WITH`가 아니면 거절합니다.
  `FOR UPDATE`, `INTO`(SELECT INTO), PL/SQL 블록(`BEGIN`·`DECLARE`), `CALL`·`EXEC`는 거절합니다.
  - 문장 검사는 실수를 막는 장치일 뿐 보안 경계가 아닙니다. 경계는 계정 권한과 아래의 읽기 전용 트랜잭션입니다.
- **읽기 전용 트랜잭션:** 연결마다 읽기 전용 트랜잭션을 연 뒤 조회하고, 끝나면 되돌립니다(rollback). 커밋은 하지 않습니다.
- **시간 한도:** 기본 60초입니다(연결마다 조정, 상한 300초). 넘으면 서버 쪽 취소를 요청하고 연결을 닫습니다.
- **행 수 한도:** 기본 100,000행입니다(상한은 Q6 답을 보고 정함). 한도 + 1행까지 읽어 넘으면 **파일을 만들지 않고** "한도를 넘었습니다 — 조건을 좁히세요"로 끝냅니다. 잘린 결과를 만들지 않습니다.
- **열 수·셀 한도:** 기존 업로드 한도(열 수·셀 길이·xlsx 셀 32,767자)를 그대로 적용합니다. 긴 텍스트(LOB)는 한도까지만 읽고, 넘으면 그 실행을 실패로 둡니다.
- **바인드 변수만:** 기준일 등 변수는 바인드 변수로 넘깁니다. 조회문에 문자열로 끼워 넣지 않습니다 (7장).

### 4-2. DB 종류별

| 종류 | 드라이버 (8장) | 읽기 전용 트랜잭션 | 시간 한도 | 비고 |
|---|---|---|---|---|
| Oracle | python-oracledb Thin | `SET TRANSACTION READ ONLY` | `connection.call_timeout`(ms) | 서버 12.1 이상만. 결과는 `fetchmany`로 나눠 읽음 |
| PostgreSQL | psycopg 3 (이미 있음) | `BEGIN READ ONLY` + 세션 `default_transaction_read_only=on` | `statement_timeout` | 이름 있는 커서(서버 쪽)로 나눠 읽음 |
| MySQL·MariaDB | PyMySQL | `START TRANSACTION READ ONLY` | MySQL `max_execution_time`(SELECT 전용) · MariaDB `max_statement_time` + 읽기 시간 한도 | |
| MS SQL Server | (Q1 답에 따라 따로 검토) | 읽기 전용 트랜잭션 문이 없음 — 계정 권한(읽기 역할)에 더 기대고, 연결 옵션 `ApplicationIntent=ReadOnly`는 가용성 그룹의 보조 복제본으로 보내는 용도일 뿐임 | `LOCK_TIMEOUT` + 클라이언트 시간 한도 | 드라이버(ODBC)가 이미지 크기·폐쇄망 설치에 영향이 커서 따로 정함 |

### 4-3. Elasticsearch·Kibana

- **허용한 인덱스 패턴만** 씁니다. 연결 등록 때 패턴 목록(예: `stats-daily-*`)을 정하고, 조회마다 대상 인덱스가 그 안에 있는지 확인합니다. 와일드카드 `*` 하나만 쓰는 것은 거절합니다.
- **조회 API만** 부릅니다. 앱이 만드는 요청은 다음 셋입니다. 다른 경로·메서드는 클라이언트 코드에 없습니다.
  - `POST <인덱스>/_search`
  - (판이 지원하면) `POST _query`(ES|QL) 또는 `POST _sql?format=json`
  - 연결 시험용 `GET /`
- **API 키 권한은 인덱스 `read`만** 받기를 권합니다 (Q4). 클러스터 권한은 필요 없습니다.
- **한도:** `size`·결과 행 수 한도는 DB와 같습니다. 10,000행이 넘는 결과는 point-in-time + `search_after`로 나눠 읽고, 한도를 넘으면 파일을 만들지 않습니다. 요청 본문의 `timeout`과 클라이언트 시간 한도를 함께 겁니다.
- **결과를 표로 만들기:** 문서 조회는 정의에 적은 필드만 열로 만듭니다(중첩 필드는 `a.b`). 집계(aggregation)는 버킷 키 + 지표를 행으로 펼칩니다.
- **Kibana 저장 검색을 쓸 때:** Kibana에서 저장 검색의 정의(인덱스 패턴·조회·열)를 읽어 Elasticsearch 조회로 바꿔 실행합니다. 이렇게 하려면 Elasticsearch에 직접 닿아야 합니다.
  - Kibana만 열려 있으면(Q2) Kibana 보고서(CSV) 기능을 거치는 방법이 남습니다. 이 방법은 비동기이고 보고서 권한이 필요해 따로 검토합니다. Kibana의 개발자 도구 중계 경로는 쓰지 않습니다.

## 5. 접속 범위 (폐쇄망 원칙 유지)

### 5-1. 허용 규칙

- **등록한 호스트만** 접속합니다. 연결 정보(호스트·포트·서비스 이름/DB 이름·TLS 설정)는 소유자가 화면에서 등록하고, 앱은 다른 곳으로 접속하지 않습니다.
- **사설·내부 주소만** 허용합니다. 접속 직전에 호스트 이름을 해석해 루프백·사설 대역(10/8, 172.16/12, 192.168/16)·`host.docker.internal`이 아니면 거절합니다.
  - 해석한 주소로 바로 접속합니다. 이렇게 하면 시험 때와 실행 때 다른 주소로 바뀌는 DNS 재지정을 막습니다. TLS는 원래 이름으로 검증합니다.
  - 사내 대상이 공인 주소 대역을 쓴다면(Q3) 그 대역을 소유자가 명시적으로 등록하는 예외를 둘지 따로 정합니다.
- 지금 Ollama 주소를 로컬로 제한하는 검사(`app/ollama.py` `_check_local`)와 같은 자리에서 확인합니다.
- 리다이렉트를 따라가지 않습니다(HTTP). 프록시 환경 변수를 쓰지 않습니다.

### 5-2. 컨테이너에서 사내망까지

운영은 Docker Desktop의 기본 bridge 망에서 돕니다. 컨테이너의 바깥 연결은 호스트(Windows)의 경로를 따라 나갑니다.
VPN을 쓰는 사내망이면 VPN 클라이언트에 따라 WSL·Docker의 트래픽이 VPN을 타지 않을 수 있습니다.
그래서 **대상 정보(Q3)를 받은 뒤 소유자 승인 하에 연결 시험 1회**로 실제 경로를 확인합니다 (9-2).
compose 망 설정은 이 확인 결과를 보고 바꿀지 정합니다(지금은 바꾸지 않음).

## 6. 비밀값

- **DB에 평문으로 저장하지 않습니다.** 비밀번호·API 키는 AES-256-GCM(`cryptography`)으로 암호화해 `data_connections.secret`에 저장합니다.
  - 저장 값: 키 ID · 임의 nonce · 암호문.
  - 연결 번호와 판을 추가 인증 데이터(AAD)로 묶어, 다른 행에 옮겨 붙인 암호문은 풀리지 않게 합니다.
- **암호화 키는 데이터 볼륨과 백업 밖에 둡니다.**
  - 키 파일 경로는 환경 변수 `MOAJWO_CONN_KEY_FILE`로 받습니다.
  - 컨테이너에는 읽기 전용으로 마운트합니다. 호스트 쪽 위치는 데이터 폴더·백업 폴더가 아닌 곳(예: 사용자 프로필 아래 보호된 폴더)입니다.
  - 키 파일은 설치 담당자가 한 번 만듭니다(32바이트 임의값, 본인만 읽기). 앱은 만들지 않고 없으면 '데이터 연결'을 쓸 수 없다고 알립니다.
- **키를 잃으면** 저장한 비밀값을 풀 수 없습니다. 연결 정보는 남고, 화면이 "비밀값을 다시 입력하세요"로 안내합니다. 데이터·조회·실행 기록에는 영향이 없습니다.
- **키 교체:** 새 키 ID로 다시 암호화하는 관리 명령(`python -m app.connkey rotate`)을 둡니다. 옛 키는 교체가 끝난 뒤 지웁니다.
- **어디에도 남기지 않음:**
  - API 응답에는 `has_secret: true/false`만 둡니다 (값·길이·일부 글자 없음).
  - 로그·관리 이력에는 "비밀값을 바꿨습니다"만 남깁니다.
  - 백업 기록은 DB 사본만 담고 키 파일은 담지 않습니다.
  - 오류 문구: 드라이버 예외에 접속 문자열이 섞일 수 있어, 화면·로그에는 정해 둔 분류(연결 실패·인증 실패·시간 초과·권한 없음·조회 오류)와 정제한 요약만 보입니다.
- 비밀값 입력 칸은 다시 보여 주지 않습니다(빈 칸 = 그대로 둠). 운영 화면은 이 PC의 127.0.0.1에서만 열리므로(HTTP) 비밀값은 이 PC 안에서만 오갑니다. 화면을 다른 PC에서 열게 되면 그 전에 HTTPS를 둡니다.

## 7. 기준일 변수

### 7-1. 변수

| 변수 | 뜻 (한국 시간 기준) | 예: 기준일 2026-11-06 |
|---|---|---|
| `:base_date` | 기준일 (실행 때 고름, 기본 오늘) | 2026-11-06 |
| `:yesterday` | 기준일 전날 | 2026-11-05 |
| `:month_start` · `:month_end` | 기준일이 속한 달의 첫날·끝날 | 2026-11-01 · 2026-11-30 |
| `:last_month_start` · `:last_month_end` | 지난달 첫날·끝날 | 2026-10-01 · 2026-10-31 |
| `:base_month` | 기준일의 달 (`YYYY-MM`, 검증의 기준 기간과 같은 꼴) | 2026-11 |

- **DB:** 조회문에는 바인드 변수 이름으로 씁니다(`WHERE stat_date = :yesterday`). 드라이버마다 자리 표시 방식이 달라 앱이 바꿔 넘깁니다. 날짜는 날짜 형식으로 넘깁니다 — 문자열을 조회문에 끼워 넣지 않습니다.
- **Elasticsearch:** 조회 정의의 `range` 값 자리에 같은 이름을 쓰고, 앱이 날짜 문자열로 바꿔 넣습니다(JSON 값만 — 키·필드 이름에는 못 씀).
- 실행 기록에 **해석된 값**(예: `yesterday=2026-11-05`)을 남깁니다. 기준 기간이 있는 검증에는 `:base_month`를 기본값으로 넘깁니다.

### 7-2. 정의 판

조회 정의를 고치면 판이 +1 됩니다(저장한 작업의 `expected_version`과 같은 방식 — 다른 창이 먼저 고쳤으면 409).
실행 기록은 실행한 판을 남깁니다.

### 7-3. 정기 실행에 대비

실행은 `run_saved_query(query_id, base_date, actor)` 한 함수로 둡니다. 같은 입력이면 같은 일을 하고, 화면 요청과 무관하게 부를 수 있습니다.
나중에 정기 실행을 붙일 때는 Windows 작업 스케줄러(지금 주간 백업과 같은 방식)가 관리 명령(`python -m app.queryrun <조회> --base-date yesterday`)을 부르게 합니다.
같은 (조회, 기준일)의 중복 실행은 0021의 요청 번호처럼 막습니다. 이번 범위에서는 만들지 않습니다.

## 8. 드라이버·이미지 영향

2026-11-06에 backend 이미지와 같은 Python 3.11 · manylinux x86_64용 wheel을 내려받아 잰 값입니다 (설치하지 않음, 회차 기록에 sha256).

| 패키지 | 판 | wheel | 풀린 크기 | 쓰임 | 비고 |
|---|---|---|---|---|---|
| python-oracledb | 26.1.0 | 2.9 MB | 8.6 MB | Oracle | **Thin 모드는 Oracle Instant Client가 필요 없음** — 순수 Python + 컴파일된 확장. Thick 모드(Instant Client)는 쓰지 않는 것이 기본안 |
| cryptography | 50.0.2 | 4.8 MB | 15.0 MB | 비밀값 암호화 + oracledb의 의존성 | cffi 2.1.1(0.7 MB)·pycparser 3.12(0.3 MB) 함께 |
| PyMySQL | 1.2.3 | 0.05 MB | 0.1 MB | MySQL·MariaDB | 순수 Python |
| psycopg | 3.3.6 | — | — | PostgreSQL | **이미 있음** (외부 DB용) |
| (Elasticsearch) | — | — | — | ES·Kibana | **새 패키지 없음** — 표준 라이브러리 HTTP(Ollama 호출과 같은 방식) |

- **이미지 크기:** 지금 backend 이미지 327 MB(2026-11-06 운영 이미지)에 약 25 MB(Oracle·MySQL을 모두 넣을 때)가 늘어날 것으로 봅니다. 실제 값은 도입 PR의 image-gate로 잽니다. Q1 답에 따라 필요한 드라이버만 넣습니다.
- **취약점 점검:** 도입 PR에서 image-gate(Trivy)로 새 패키지를 점검합니다. 수정판이 없는 HIGH 이상이 나오면 기존 규칙대로 소유자 판단을 받습니다.
- **폐쇄망 설치:**
  - 위 패키지는 모두 wheel로 받을 수 있어 빌드 때 인터넷 없이 설치할 수 있습니다(`pip install --no-index --find-links`, requirements에 해시 고정).
  - 운영 반영은 지금처럼 이 PC에서 이미지를 빌드합니다. 빌드할 때 패키지 저장소에 닿아야 하는 점은 지금과 같습니다.
- **Oracle Thin 모드 제약 (python-oracledb 공식 문서의 Thin·Thick 기능 비교표, 2026-11-06 확인):**
  - 서버 12.1 이상만 지원합니다 (Thick 모드는 11.2 이상).
  - Oracle Client 라이브러리(Instant Client)가 필요 없습니다.
  - **네이티브 네트워크 암호화(NNE)를 지원하지 않습니다** — 문서는 TLS(또는 암호화만 하는 TLS)를 쓰라고 안내합니다. 사내 DB가 NNE만 받으면 Thick 모드(Instant Client)가 필요합니다. Q1·Q5 답으로 정합니다.
  - Instant Client가 필요해지면 이미지가 수십~백 MB 늘고 Oracle 라이선스 조건 확인이 필요해, 따로 승인받습니다.

## 9. 시험 계획

### 9-1. CI (합성 자료만)

PC 메모리가 빠듯하므로 큰 시험 환경은 PC가 아니라 CI(진단 가지 `ci/**`)의 서비스 컨테이너로 돌립니다.

| 대상 | 이미지 (도입 PR에서 digest 고정) | 시험 |
|---|---|---|
| Oracle | Oracle Database Free(23ai) 컨테이너 | 연결 시험·조회·미리보기·실행. 쓰기 문장 거절. 읽기 전용 트랜잭션에서 DML 오류(ORA-01456). 시간 한도. 행 수 한도(한도+1에서 파일 없음). 바인드 변수 |
| PostgreSQL | `postgres:17` | 위와 같음 (`25006 read_only_sql_transaction`) |
| MySQL | `mysql:8.4` | 위와 같음 |
| Elasticsearch | `elasticsearch:8.x` 단일 노드, 보안 켬 + 인덱스 `read` 전용 API 키 | 허용 패턴 밖 인덱스 거절. 쓰기 API를 부르지 않음(클라이언트 경로 목록). 10,000행 넘는 결과 나눠 읽기. 집계 펼치기. 날짜 변수 |

공통 시험:
- 비밀값이 응답·로그·관리 이력·백업 기록에 없는지 (문자열 검색)
- 키 파일이 없을 때·틀렸을 때의 안내
- 공인 주소·DNS 재지정 거절
- 0025 upgrade·downgrade (SQLite·PostgreSQL)
- 등록 파일의 sha256 = 스냅숏 · 개인정보 탐지가 업로드와 같음
- 화면 시험: 390px·키보드·200%

### 9-2. 실제 사내 대상

소유자 승인 뒤 **읽기 1회만** 확인합니다: 연결 시험 + 예시 조회 1개 미리보기(최대 N행).
결과 값은 기록에 남기지 않고 행·열 수와 열 이름만 남깁니다(열 이름이 민감하면 가림).

## 10. 권한

- 연결 등록·수정·삭제·비밀값 입력은 **최고 관리자(소유자)만** 합니다 (기본안, Q9).
- 저장한 조회의 정의·실행도 처음에는 소유자만 합니다. 일반 사용자에게 열 때는 따로 정합니다(연결별 허용 목록).
- 다른 사용자의 연결·조회는 있는지조차 알리지 않습니다(404 — 저장한 작업과 같은 규칙).

## 11. DB 변경 — 0025 (예정)

| 표 | 주요 열 |
|---|---|
| `data_connections` | `id`(다시 쓰지 않음) · `owner_id` · `name` · `kind`(oracle/postgresql/mysql/elasticsearch) · `host` · `port` · `service`(서비스 이름/DB 이름) · `username` · `secret`(암호문·키 ID·nonce) · `options`(TLS·CA 경로 이름·시간/행 한도·허용 인덱스 패턴, JSON) · `version` · `created_at` · `updated_at` |
| `saved_queries` | `id` · `connection_id` · `owner_id` · `name` · `definition`(SQL 또는 ES 조회, JSON) · `params`(쓰는 변수 목록) · `row_limit` · `timeout_s` · `version` · `created_at` · `updated_at` |
| `query_runs` | `id` · `query_id` · `query_version` · `base_date` · `resolved_params`(JSON) · `status`(성공·실패·한도 초과) · `rows` · `columns` · `source_file_id`(등록한 원본 파일) · `sha256` · `started_at` · `duration_ms` · `error_kind` · `actor_id` |

- 원본 파일 표(`source_files`)에는 출처 열 하나(`origin_query_run_id`, 비어 있으면 업로드)를 더하는 안과, `query_runs.source_file_id`로만 잇는 안이 있습니다. 기존 표를 바꾸지 않는 뒤쪽을 기본안으로 합니다.
- **되돌리기(downgrade 0025 → 0024):**
  - 세 표만 지웁니다. 실행으로 등록된 원본 파일과 그 뒤의 검토·실행 기록은 일반 업로드 파일처럼 남습니다(출처 정보만 사라짐).
  - downgrade 전에 백업을 받습니다. "이미지만 이전 판으로 바꾸는 롤백은 하지 않는다" 규칙에 따라, 0025 이미지를 되돌릴 때는 downgrade를 먼저 합니다.
- **백업·복원:**
  - 주간·반영 전 백업에 세 표가 함께 들어갑니다(암호문 포함, 키 없음).
  - 다른 PC나 새 키로 복원하면 비밀값을 다시 입력해야 합니다. 복원 확인 절차에 "비밀값 풀림 여부"를 항목으로 더합니다.
- SQLite·PostgreSQL 두 DB에서 같게 동작하도록 기존 마이그레이션 규칙(번호 재사용 금지·이름 길이 한도·NUL 거절)을 따릅니다.

## 13. 구현 순서 (승인 뒤, PR을 나눔)

1. 0025 + 키 파일·비밀값 보관 + 연결 등록·시험 (Q1의 첫 DB 한 종류)
2. 저장한 조회 정의·미리보기·기준일 변수
3. 실행 → 원본 파일 등록 (업로드의 등록 부분 `app/files.py` `_handle_one`을 함께 쓰는 함수로 나눔)
4. Elasticsearch (Kibana 저장 검색은 Q2 답에 따라)
5. (별도 승인) 정기 실행

각 단계는 지금처럼 Draft PR → CI(static·pytest·image-gate + 서비스 컨테이너 시험) → 소유자 승인 → 병합 → PC를 새로 켠 직후 `scripts/deploy.sh` 반영입니다.
0025가 들어가는 반영은 DB 변경 반영이므로 반영 직전 백업과 downgrade 확인을 함께 합니다.
