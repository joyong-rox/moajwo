# 개인정보 출력 정책

Moajwo가 개인정보 형식의 값을 어디서 가리고 어디서 원본 그대로 두는지 정리합니다. 세 정책은 서로 다릅니다.

1. **화면 가림:** 사람이 보는 화면·응답을 가립니다.
2. **분석 출력 가림:** 새로 계산한 결과를 가립니다.
3. **원본 데이터 출력:** 권한자가 포함을 확인한 원본을 그대로 옮깁니다.

## 가리는 대상

- **개인정보 형식:** 이메일, 휴대전화, 주민등록번호 (`backend/app/pii.py`)
  - 예: `kim1@example.com` → `k***@example.com`
  - 예: `010-1234-5678` → `010-****-5678`
  - 예: `900101-1234567` → `900101-1******`
- **가리지 않는 것:** 유선전화·계좌번호·IP 등은 이 형식에 들지 않아 가리지 않습니다. 사람 이름만으로는 개인정보로 판단하지 않습니다.
- **성질** (확인 2026-10-22):
  - 가림은 반복 적용해도 결과가 같습니다.
  - 7자리 기관 코드·해시·날짜·쉼표 숫자·큰 정수는 바꾸지 않습니다.
  - 숫자 칸의 자료형도 바꾸지 않습니다 (정수는 정수).

## 1. 화면 가림 — 화면·API 응답

| 대상 | 규칙 |
|---|---|
| 파일·시트·열 이름, 셀 미리보기, 검증·검토 사유, 실행 요약·변경 기록, 승격 심사 | 응답을 만들 때 가립니다. DB의 기록은 연결용 원문 그대로 둡니다. |
| 시트·열 지정 | 이름 대신 `sheet_id`·`column_id`로 받습니다. 가린 이름이 겹쳐도 정확한 대상을 찾습니다. |
| 개인정보 형식이 든 기관·지역 이름 | 별칭으로 등록하지 않습니다 (등록 API 422, 검토 완료 학습 제외). |

## 2. 분석 출력 가림 — 데이터 통계 분석, 묶기 '통계 요약'

| 대상 | 규칙 |
|---|---|
| 결과의 구분 값, 파일·시트·열 이름, 사용자가 적은 구간 이름·필터 값·단위 | 화면·저장·Excel 모두 가립니다. |
| 가린 뒤 같아진 서로 다른 값 | 계산은 원래 대상으로 따로 하고, 표시는 '(가림 구분 n)' 번호로 구분합니다 (F-1, PR #22). 원문이나 원문의 단순 해시를 결과에 저장하지 않습니다. |
| Excel 글자 칸 | 수식으로 저장되지 않게 합니다. |
| 공통 key 연결의 확인 응답·실행 기록·오류 문구 | key 원문·가린 key·해시를 넣지 않습니다 — 위치(입력 번호·파일 번호·시트 순번·열 문자·행 번호)·개수·코드만. 미리보기(앞 20행)는 가린 key·가린 값이며, 가린 뒤 같아진 서로 다른 key는 합치지 않고 '(가림 구분 n)'으로 구분합니다 ([KEYJOIN.md](KEYJOIN.md)). |

## 3. 원본 데이터 출력 — 통합 결과, 묶기 데이터 시트, 공통 key 연결 결과

| 대상 | 규칙 |
|---|---|
| 개인정보가 탐지된 파일 (머리글에만 있어도) | 포함을 **확인**해야 결과에 들어갑니다. 통합은 사전 검토에서 승인, 묶기·공통 key 연결은 계획(연결 확인)에서 확인합니다. 거부하거나 뺀 파일은 결과에 들어가지 않습니다. |
| 공통 key 연결 결과 (「연결 결과」 시트) | 서버는 원래 key로 연결하고 결과 데이터에는 원래 key·고른 열의 원본 값을 담습니다. 선택하지 않은 열은 어느 시트에도 넣지 않고, 「출처」·「연결 요약」 시트에는 key 원문·셀 값이 없습니다. |
| 결과 파일의 값 | 결과 데이터라 원본 값을 **가리지 않고** 담습니다. 화면이 내려받기 전에 이를 안내합니다. |
| 내려받기 권한 | 그 실행 기록을 볼 수 있는 사람(본인·최고 관리자)만 내려받습니다. |
| 기존 결과 파일 | 일괄 수정하지 않습니다. 포함을 확인한 결과를 나중에 임의로 가리지도 않습니다. 새 출력 정책이 필요하면 미리보기·동의·실행 기록·내려받기를 함께 설계합니다. |

## 오류 응답과 기록

| 대상 | 규칙 |
|---|---|
| 요청 형식 오류 (422) | 필드 위치(`loc`)·오류 종류(`type`)·안내(`msg`)만 보냅니다. 보낸 값(`input`)은 되돌려 보내지 않습니다. |
| 업무 오류 (409·403·404·422 안내문) | 사유에 이름이 들어가면 가림을 적용합니다. 비밀번호·토큰·API Key는 넣지 않습니다. |
| 접근 기록 — backend(uvicorn)·frontend(nginx) | 요청 경로는 남기고 쿼리 값은 남기지 않습니다. 예: `GET /users?q=…&status=…`, nginx는 `GET /api/users`. 출처(referer)·브라우저 정보도 남기지 않습니다. |
| 앱 기록 | 건수·상태·번호만 남깁니다. 오류 응답의 원문 값을 기록하지 않습니다. |

**바꾸기 전 (main `adebb6c`):**
- 422 기본 응답이 보낸 본문 전체를 담았습니다. 로그인에서 아이디를 빠뜨리면 비밀번호가, 가입 신청 형식 오류에서는 비밀번호·이메일·전화번호가 응답에 나왔습니다.
- 접근 기록에는 관리자 사용자 검색어 같은 쿼리 값이 그대로 남았습니다.

## 바꾸지 않은 것

- 화면·분석의 가림 규칙과 개인정보 형식의 범위
- 통합·묶기 결과의 원본 값
