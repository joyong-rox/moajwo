**안전한 롤백 준비: 완료 (조건부)** — 근거: ① 0022를 유지하는 수정판 경로는 평소 반영 경로(`scripts/deploy.sh`)와 같고, 구판으로 돌아가는 B′는 덧붙임 설정만으로
공개 가입을 막는 것을 진단 CI 리허설(문서의 P1·P0 상자를 그대로 실행)과 운영 이미지 태그(구판)로 돌린 격리 리허설에서 확인했으며(아래 7절 측정값), 변경을
요청할 수 없는 **이용 중지** 임시 계정은 「임시 비밀번호 폐기」로 downgrade 보호 조건 밖으로 내보낼 수 있다. 조건: **이용 중** 임시 계정이 남아 있으면 B′·A의

리허설했다(6차 2026-10-31: 0021→0022 → B 1~7 → P1 → P0 → 다시 0022, `backups/followup-20261030/round6/COPY-REHEARSAL.md`) — 운영 환경 자체에 되돌린 적은 없고, Render용 B′는 없다.

소유자 결정(2026-10-31, D2): **① 수정판(fix-forward)이 표준**, **B′는 비상시에만**(B 1~7단계 + P1 — 구판 이미지는 고치지 않고 배포 설정만으로 `POST /api/auth/signup`
차단, 되돌리기 쉬움), **A(백업 복원)는 자료 손상으로 자료 복구가 필요할 때만**이며 이때도 P1을 적용한다. 어느 경로도 자동 실행하지 않는다 — 승인 뒤 사람이 상자를

## 1. 장애가 났을 때 가장 먼저 (어느 경로든 공통)

1. **멈추고 보존**: 새 반영 직후의 장애면 `docker compose stop -t 30 frontend backend`로 쓰기를 멈추고, 지금 DB·파일(`moajwo_moajwo-data` 볼륨)·실행 중이던
   이미지 ID(`docker inspect moajwo-backend-1 --format '{{.Image}}'`)·반영 로그(`backups/deploy-<시각>.log`)를 그대로 둔다. 볼륨 백업은 B 2단계가 만든다 —
   따로 만들려면 2단계 상자만 먼저 붙여 넣어도 된다(0·1단계 뒤).
2. **분류**: (가) 앱 결함(500·화면 오류·기능 불가) → ①. (나) 자료 손상(DB 무결성 실패·파일 유실·잘못된 일괄 변경) → A + P1(③), 그 전에 손상 범위와 백업 시점을
   확인. (다) 환경 문제(디스크·메모리·Docker) → 복구 경로가 아니라 환경을 고친 뒤 `docker compose start backend frontend`.
3. **임시 상태 계정 확인**(B′·A를 생각한다면 먼저): 「관리자 → 사용자 계정」의 '비밀번호' 열, 또는 정지 상태에서
   `docker run --rm --entrypoint python -v moajwo_moajwo-data:/data:ro moajwo-backend:latest -c "import sqlite3; c=sqlite3.connect('file:/data/moajwo.db?mode=ro', uri=True); print(c.execute('select username, status from users where must_change_password').fetchall())"`
   — 결과가 비어 있어야 downgrade가 통과한다(2절).
4. **결정 기록**: 선택한 경로·이유·시각을 반영 로그 옆(`backups/`)에 메모로 남긴다. ②·③은 소유자 승인이 있어야 한다.

## 2. 임시 상태 계정이 남아 있을 때의 처리 순서 (D3)

| 계정 | 처리 | 하지 않는 것 |
|---|---|---|
| **이용 중** + 임시 비밀번호(만료 포함) | 사용자에게 본인 비밀번호 변경을 요청하고 기다린다(만료됐으면 재발급 뒤 변경). 기다릴 수 없으면 "이 경로의 downgrade는 쓸 수 없다"고 안내하고 ①로 간다 | downgrade를 통과시키려고 이용 중지시키거나 플래그를 지우지 않는다 — 폐기 대상이 아니다 |
| **이용 중지** + 임시 비밀번호 | 관리자가 「임시 비밀번호 폐기」(화면 버튼 또는 `POST /users/{id}/password/revoke`, `expected_auth_version` 필수 — [DEPLOY.md](DEPLOY.md) 12-6). 비밀번호가 사용할 수 없는 값이 되고 임시 상태가 풀려 보호 조건 밖으로 나간다. 구판에서도 로그인할 수 없고, 복귀 뒤 재개하려면 재발급한다 | DB에서 `must_change_password`만 지우지 않는다(플래그만 지우는 경로는 없다) |
| 이용 중지 + 본인 비밀번호 | 보호 조건과 무관 — 그대로 둔다 | — |

확인: 위 3번 조회가 빈 목록이면 된다. 실행 중인 결과 실행(담당 있음)도 B 3·4단계가 정리한다.

## 6. 운영 규칙 요약

- 이미지만 되돌리지 않는다(이전 포트 파일과 함께, 4장). 구판 이미지는 고치지 않는다(B′는 덧붙임 설정만). `down -v`·자동 downgrade·일괄 실패 처리는 하지 않는다.
- 0022 이후 판의 구판 복귀는 **P1까지가 한 묶음**이다. B(P1 없이)는 허용하지 않는다.
- 되돌린 동안의 공지: "임시 계정 발급·재발급·폐기는 복귀 뒤에" — 구판에는 그 기능이 없다. 0022에서 폐기한 계정은 구판에서도 로그인할 수 없다.
- **관찰 기간 규칙(소유자 결정 2026-10-31, 6·7차):** 0022 반영 뒤 소유자가 **관찰 종료를 판정할 때까지 임시 비밀번호 신규 발급·재발급을 하지 않는다**(원칙) — B′
