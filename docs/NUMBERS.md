# 숫자 정밀도 계약

통계 결과의 숫자를 어떻게 읽고, 어떤 정밀도로 계산하고, 언제 반올림하며, 화면·API·Excel로 어떻게 넘기는지 정한 규칙입니다. 화면 자릿수를 줄여 정확해 보이게 하지 않고, 실제 계산을 정확하게 합니다. 담을 수 없는 경계는 숨기지 않고 알립니다.

- 적용: 데이터 통계 분석(`backend/app/analysis.py`)과 그 엔진을 쓰는 묶기 '통계 요약'
- 경계 사례 시험: `backend/tests/test_precision.py`

## 1. 읽기 (자료형)

| 종류 | 예 | 읽는 방법 |
|---|---|---|
| 정수 수량 | 인원·대수·건수·원 | 숫자 칸은 정수 그대로 읽습니다. 숫자 글자('1,234')는 실수(float)를 거치지 않고 정수로 읽습니다 (`parsing.to_number`). |
| 소수 수량 | 면적·비율이 아닌 소수 값 | 원본에 적힌 자릿수로 읽습니다. 그 값을 되살리는 가장 짧은 십진 표기를 쓰므로 0.1은 0.1입니다. |
| 비율·증감률 | % | 더해서 뜻이 있는 값이 아니라 합계·평균 대상이 아닙니다 (1차 분석 범위 밖). |
| 식별자 | 코드·번호 | 글자로 보존하고 합산하지 않습니다. 선행 0과 15자리를 넘는 자릿수를 그대로 둡니다. |
| 결측·비공개 | 빈칸, '-', 'x', '…', '비공개' | 0으로 바꾸지 않고 사유와 함께 뺍니다 (그 그룹은 '부분 집계'). 음수와 0은 유효한 숫자입니다. |

**xlsx의 한계:** xlsx 숫자 칸은 배정밀도라 2^53(9,007,199,254,740,992)을 넘는 정수를 담지 못합니다. 이런 값은 파일에 쓰는 순간 바뀌므로, 정확한 큰 정수는 CSV나 글자 칸으로만 들어옵니다. **Excel에서 이미 잃은 자릿수는 복원하지 않습니다.**

## 2. 계산

- **합계:** 각 행의 정확한 수로 더합니다. 정수는 정수 그대로, 소수는 원본 자릿수의 십진수로 더합니다 (Python `Decimal`, 유효 숫자 28자리).
  - 0.1 + 0.2 = 0.3
  - 2^53 + 1 과 1의 합 = 9,007,199,254,740,994 (끝자리까지)
- **평균:** 정확한 합 ÷ 유효한 숫자 개수를 마지막에 한 번만 배정밀도로 바꿉니다. 파일별 평균을 다시 평균하지 않습니다.
- **최솟값·최댓값:** 정확한 값 그대로입니다.
- **구간 분류:** 정확한 합으로 경계를 비교합니다. 합 0.3은 '0.3 이하(포함)' 구간에 들어갑니다 — 예전에는 0.30000000000000004라 빠졌습니다.
- **상·하위 지역 비교:** 정확한 값으로 허용 오차 없이 비교합니다 (기존 규칙 그대로 — 1원·1명 차이도 다름).
- **통합 전 검사의 합계 검사(`validation.check_sums`)는 다른 규칙입니다:** 원본 표의 합계 행이 반올림해 적힌 경우가 있어 배정밀도 합에 '하위 행 수 × 마지막 자리의 절반'만큼 허용합니다. 결과를 계산하지 않고 원본 표를 검사하기 때문입니다.

## 3. 반올림 시점

- 계산 중에는 반올림하지 않습니다. 평균만 마지막에 배정밀도로 바꿉니다.
- 화면 표시는 소수 넷째 자리까지입니다 (표시만 하며, 저장값·Excel은 그대로).
- 상·하위 비교의 값과 차이는 반올림하지 않고 보입니다.

## 4. 전달

| 경로 | 규칙 | 경계 |
|---|---|---|
| API(JSON) | 정수는 정수, 소수는 배정밀도 수 | 브라우저(JavaScript Number)는 절댓값 2^53을 넘는 정수의 끝자리를 정확히 담지 못합니다. 그런 값이 결과에 있으면 결과 조건에 주의 "절댓값이 9,007,199,254,740,992(2^53)를 넘는 정수가 있습니다…"를 남깁니다. |
| Excel (통계 분석 결과·통계 요약 시트) | 숫자 칸 | **16자리 이상 정수는 글자 칸**으로 적어 자릿수를 지킵니다. Excel 숫자 칸은 15자리까지만 정확합니다. 글자 칸은 Excel에서 바로 계산에 쓰이지 않습니다 — 자릿수 보존이 목적입니다. |
| 묶기 데이터 시트 (원본 값을 옮김) | 원본 값 그대로 | 15자리를 넘는 숫자가 있으면 계획 단계에서 경고합니다 (기존). 코드·식별자 열은 글자로 둡니다. |
| 통합 결과 | 원본 값 그대로 (확정한 수량은 계산용 값) | 수식이 아닌 글자 칸 (PR #26 — '='로 시작하는 글자) |

## 5. 경계 확인 (`tests/test_precision.py`)

| 사례 | 바꾸기 전 | 지금 |
|---|---|---|
| 0.1 + 0.2 | 합 0.30000000000000004 | 합 0.3, 평균 0.15 |
| 10.4 + 20.4 | 합 30.799999999999997 | 합 30.8 |
| 합 0.3과 '0.3 이하(포함)' 구간 | 구간 밖 | 구간 안 |
| (2^53 + 1) + 1, CSV | 9,007,199,254,740,992 (끝자리 틀림), 알림 없음 | 9,007,199,254,740,994, 주의 남김, Excel 글자 칸 |
| 1,234,567,890,123,456 + 4 (16자리) | Excel 숫자 칸 (15자리만 정확) | Excel 글자 칸 '1234567890123460' |
| 1,000,000,000,001 + 999,999,999,999 + 500 | 정확 (2^53 안) | 정확 |
| -5, 0, '-', 'x', 10 | 합 5 · 개수 3 · 부분 집계 | 같음 |

## 6. 그대로 둔 것

- **확정 수량 해석 분리(PR #9):** 사용자가 확정한 수량 열만 계산용 값으로 바꾸고, 원문 미리보기·캐시는 바꾸지 않습니다.
- **비교·판정에 쓰는 측정 값의 형식:** 반복·파일 사이 중복의 '값 같음/다름' 비교 등은 그대로입니다. 바뀐 것은 집계와 근거 행 값뿐입니다.

## 7. 남은 제한

- **화면:** 2^53을 넘는 정수의 끝자리를 정확히 보이지 못합니다 (주의로 알림). 화면도 정확히 보이려면 API가 그런 값을 글자로 함께 보내야 하며, 이것은 별도 결정입니다.
- **아주 큰 합:** 유효 숫자 28자리를 넘는 합(10^28 이상)은 28자리에서 반올림됩니다.
- **글자 칸으로 보존한 값:** Excel에서 바로 계산에 쓰려면 사용자가 판단해 바꿔야 합니다.
