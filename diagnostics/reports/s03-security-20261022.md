# 실행 중 권한·세션·응답 헤더 확인 (S-03, 2026-10-22)

- **대상:** main `adebb6c` + PR #29(S-02) + 이 PR의 변경
- **기준:** OWASP ASVS를 요구사항 목록으로만 참고했습니다. 도구 통과나 검출 0건을 전체 보안 검증 완료로 쓰지 않습니다.

## 방식

- **구성:** 격리 구성을 운영과 같은 형태로 띄웠습니다.
  - 공식 nginx 1.30.6(Windows)이 이 브랜치 빌드본을 `127.0.0.1:8086`에서 내보냅니다.
  - `/api/`는 격리 backend(`127.0.0.1:8096`, 새 데이터 폴더, 모델 호출 차단)로 넘깁니다.
  - Docker가 꺼져 있어(운영 재시작 금지) 컨테이너 대신 이 구성을 썼습니다.
- **요청:** 앱의 정상 API·화면으로만 보냈습니다. 진단 범위 도구(`diag_scope`)는 그 주소 하나만 허용합니다.
  - 계정과 자료는 이 실행이 새로 만든 것만 썼습니다.
  - 대량 요청·무차별 대입·운영 계정 잠금·실제 개인정보는 쓰지 않았습니다.
- **10-20 진단과의 관계:** 10-20 진단에서는 실행 중 권한 확인 스크립트를 쓰던 응답이 도구에 의해 중단되어 미수행으로 남았습니다. 그 스크립트를 되살리거나 우회하지 않았습니다. 이번에는 아래 두 진단 스크립트를 새로 작성했습니다.
  - `scripts/authz_matrix.py` (권한표)
  - `scripts/csp_check.py` (화면·CSP)

## 1. 자원별 권한 (`authz_matrix.py`)

**계정:**
- A: 자료를 만든 일반 사용자
- B: 다른 일반 사용자
- O: 최고 관리자
- 익명
- A의 로그아웃한 세션
- 승인 대기 P

**A의 자원:** 파일·매핑 확정·검토(완료)·통합 실행·데이터 통계 분석·자동화·묶기 계획

**변경 요청 확인 방법:** 요청 전후로 DB 10개 표의 건수를 비교했습니다.

### 조회

| 요청 | A | B | O | 익명 | 로그아웃한 세션 |
|---|---|---|---|---|---|
| 파일 미리보기·매핑, 검토, 통합 실행·변경 내역·내려받기, 분석 결과·내려받기, 자동화 (9개) | 200 | **404** (있는지도 알리지 않음) | 200 (조회 권한) | 401 | 401 |
| 목록에 A의 것이 보이는지 (파일·실행·분석·자동화·검토) | 모두 보임 | 모두 안 보임 | 실행·자동화·검토는 보임. 파일·분석 목록은 본인 것만 | 401 | 401 |

### 변경 (A는 자기 자원이라 보내지 않음)

| 요청 | 익명·로그아웃한 세션 | B | O (최고 관리자) |
|---|---|---|---|
| 매핑 확정 `PUT /files/{id}/mapping/decisions` | 401 | 404 | **403** |
| 열 매핑 분석 `POST /files/{id}/mapping` | 401 | 404 | 200 (DB 변경 없음 — 조회용 계산) |
| 검토 변경·다시 검사·통합 | 401 | 404 | **403** |
| A의 파일로 자기 검토 만들기 | 401 | 404 | 201 (조회용 — 그 파일의 확정은 못 바꿈, README '계정과 권한') |
| A의 파일로 분석 대상 확인 | 401 | 404 | **403** (분석은 본인 파일만) |
| A의 실행으로 자동화 저장 | 401 | 404 | **403** |
| A의 자동화 실행 | 401 | 404 | 201 — 실행 기록은 O의 것. 매핑 확정 건수는 그대로 (남의 파일 확정을 쓰지 않음) |
| A의 파일로 묶기 계획 | 401 | 404 | 200 (조회 권한 범위) |
| 실행 기록 수정·삭제 `PUT/DELETE /runs/{id}` | 405 | 405 | 405 (결과는 누구도 바꾸지 않음) |
| 자동화 삭제 | 401 | 404 | 204 (코드에 명시: 저장한 사람 또는 관리자) |

- **거절된 요청이 바꾼 DB:** 모든 거절(401·403·404·405)에서 0건이었습니다.
- **판정:** 관측한 동작은 모두 README '계정과 권한'과 코드 주석에 적힌 정책과 같습니다.
  - 정책 자체를 바꿀지는 별도 결정입니다. 예: 관리자의 남의 자동화 실행·삭제 허용.

## 2. 세션·쿠키·교차 출처

| 확인 | 결과 |
|---|---|
| 로그인 쿠키 | `moajwo_session`; HttpOnly; SameSite=strict; Max-Age=43200(12시간); Path=/. 값은 기록하지 않았습니다. |
| Secure | 기본은 꺼짐 (운영은 로컬 HTTP). HTTPS면 `MOAJWO_COOKIE_SECURE=1`로 켭니다 (README). Render 검토 환경 Dockerfile(PR #19)은 `true`로 둡니다. |
| 로그아웃 | 204, 쿠키 지움. 지운 세션 값을 다시 보내면 401 (서버의 세션 기록 삭제) |
| 만료 | 격리 DB에서 세션 만료 시각을 과거로 바꾸면 200 → 401 |
| 승인 대기 계정 로그인 | 403 "가입 신청을 검토 중입니다…" |
| 다른 출처의 요청 (`Origin: http://evil.example`) | 응답에 `Access-Control-Allow-*` 헤더가 없습니다 → 다른 출처 스크립트는 응답을 읽지 못합니다. 사전 요청(OPTIONS)은 405입니다. |
| CSRF | 쿠키가 SameSite=strict라 다른 사이트에서 보낸 요청에는 쿠키가 실리지 않습니다. JSON API는 HTML 폼으로 보낼 수 없습니다. 브라우저 재현은 하지 않았습니다 — 진단 범위가 한 주소뿐이고, 같은 호스트의 다른 포트는 같은 사이트로 취급됩니다. |

## 3. 응답 헤더·API 문서 (이 PR에서 고침)

**바꾸기 전** (10-20 보고 C-07·C-08):
- nginx에 보안 헤더가 없고 `Server: nginx/버전`을 보였습니다.
- `/docs`·`/redoc`·`/openapi.json`(경로 75개 스키마)이 로그인 없이 200이었습니다.

**바꾼 뒤** (격리 nginx에서 실제 응답):

| 경로 | 결과 |
|---|---|
| `/`, `/mapping`(SPA), `/assets/…`, `/api/health`, `/api/docs` | 모두 `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: same-origin`, CSP가 붙습니다. `Server: nginx`(버전 없음) |
| CSP | `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self'; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'` |
| `/api/docs`·`/api/redoc`·`/api/openapi.json` | 404. 개발·진단에서만 `MOAJWO_API_DOCS=1`로 켭니다 |

**화면 확인** (`csp_check.py`, Edge 155, CSP를 실제로 적용):
- **확인한 화면:**
  - 일반 계정: 홈·화면 업로드(진행 막대)·열 매핑·데이터 분석·묶기·검토 목록·실행 기록·자동화·내 계정
  - 최고 관리자: 홈·사전 관리·승격 심사·설정·관리자 3개 화면
- **결과:** CSP 위반 이벤트 0, 콘솔 CSP 경고 0, 페이지 오류 0, 화면 제목 정상
- **근거:** 빌드본에 인라인 스크립트·외부 자원·data URI·eval이 없습니다. 인라인 스타일은 React가 CSSOM으로 넣어 CSP에 걸리지 않습니다.
- **시험 도구 오류 1건:** 첫 실행에서 관리자 화면 주소를 잘못 적어(`/admin` — 실제는 `/moajwoAdmin`) 404 화면을 쟀습니다. 고쳐 다시 쟀습니다.
