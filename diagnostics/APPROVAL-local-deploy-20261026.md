## 3. 스크립트가 하는 일과 멈추는 곳 (`docs/DEPLOY.md` 1·2장)

승인 커밋·트리 일치 → 실행 중 컨테이너의 실제 이미지로 롤백 태그(`rollback-<시각>`)·실제 포트 연결 파일(`backups/rollback-<시각>.compose.yml`) → 빌드(서비스 그대로) → 정지·쓰는 프로세스 없음 확인 → 볼륨 전체 백업·백업에서 꺼낸 DB의 무결성·리비전·행 수 비교·sha256 재확인 → 전환(`up -d --wait`) → 리비전 `(head)`·컨테이너·이미지 확인 → '배포 단위' 줄. 정지 전 단계 실패는 서비스 그대로, 정지 뒤 백업 단계 실패는 리비전이 그대로임을 확인한 뒤 기존 컨테이너 재개. 전환 실패는 자동 롤백하지 않고 4장 안내 줄을 남깁니다.

## 4. 되돌리기 (별도 승인 후 수동 — `docs/DEPLOY.md` 4장 B)

B 단계:

0. 가장 최근 반영 로그의 배포 단위를 읽습니다. 전환에서 멈췄거나 전환 도중 끊긴 반영은 그 로그의 줄에서 읽습니다. 앞 반영은 `ROLLBACK_LOG`로 한 번만 지정합니다.
1. 확인하고 정지합니다 — 실행 중 backend = latest = 그 반영 이미지인지 봅니다. 이미 되돌린 상태는 정지 전에 거절합니다.
2. 정리 전 백업을 만들고 검증합니다.
3. `recover`를 돌립니다 (종료 0일 때만 다음 단계).
4. `status`를 봅니다 — 담당 있는 실행 중 0이어야 하고, 결과 확인 필요는 하나씩 정합니다.
5. 새 이미지로 `alembic downgrade 0019_analysis_runs`.
6. DB 리비전을 확인한 뒤 이전 이미지 + 이전 포트(`-f backups/rollback-<시각>.compose.yml`)로 띄웁니다.
7. 자동 확인 + 사람 확인(계정 로그인·이전 결과).

- 반영 뒤 생긴 자료는 그대로 남고 이전 코드가 읽습니다 (0020의 두 열만 지워짐).
- 롤백 태그 이미지가 없으면 R 상자로 이전 커밋의 이미지를 다시 만듭니다.
- A(배포 전 백업 복원)는 반영 뒤 자료가 빠지므로 별도 승인입니다. A는 이 반영의 백업만 받고, 서비스가 멈춰 있을 때만 풉니다.
