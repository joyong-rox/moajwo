## 3. 요청 번호 보존·동시 실행 정책, 0021 마이그레이션·rollback (지시 3장 · 9장 2번)

- **식별 범위**: 사용자 + 작업 종류(`request_kind`="keyjoin") + 요청 번호. 다른 사용자의 같은 번호는 독립(S9: 각자 201, 사용자별 실행 1).
- **내용 비교**: 서버가 `request_hash` = sha256(MODE, POLICY, 해시 판 1, `request_id`·`expected_basis`를 뺀 본문의 정규형)을 계산해 저장·비교. 같은 내용은 기존 실행을 **상태 그대로** 반환(failed·확인 필요를 완료로 바꾸지 않음), 다른 내용은 409, 해시 없는 이전 판 실행은 409 LEGACY, 실패한 실행의 번호 재사용은 409 USED. 결과 파일이 없어진 완료 실행은 다시 만들지 않습니다.
- **원자적 소유**: 실행 행 INSERT가 고유 색인에 막히면(`IntegrityError` → `RequestTaken`) 결과 파일을 만들지 않고 먼저 든 실행을 돌려줍니다. 프로세스 안 `_IN_FLIGHT` 보호(503 output_busy)는 그대로.
- **0021 `0021_run_request_key`**: `runs.request_kind/request_id/request_hash` + 고유 색인. 채우기는 기존 실행의 summary JSON에서; 같은 사용자·종류·번호가 둘 이상이거나 요약을 읽을 수 없으면 **올리지 않고 멈춥니다**(삭제·덮어쓰기 없음, `docs/DEPLOY.md` 10장). upgrade/downgrade·채우기·거절을 SQLite·PostgreSQL 17 시험으로 확인. 복구 도구는 0020·0021 모두 다루고 진단 문구에 실제 리비전을 씁니다. 롤백 B는 0021→0020(→0019는 기존 절차).
- **문구 구분** (`docs/KEYJOIN.md`): 시작 전 422/404/409/503 거절 = 새 실행·결과 파일 없음 · 시작 후 실패 = 실패 실행·복구 근거가 남을 수 있음 · 결과는 있으나 DB 완료 미확정 = '결과 확인 필요'·파일 보존 · 완료 요청 재전송 = 기존 실행 반환·새 생성 없음 · 기존 결과 410 = 파일 없음 안내·자동 재생성 없음.
- **배포 기본은 1 worker·1 instance·기존 차례 수 그대로** — 0021은 같은 요청을 하나로 만들 뿐 다중 프로세스 전체 메모리 보호가 끝난 것이 아닙니다(`docs/MEMORY.md`).
