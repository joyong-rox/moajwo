## 2. 멈춘 실행 정리 (#41, 지시 3-1)

- **담당과 생존 신호** (`backend/app/runlease.py`, 마이그레이션 0020): 실행마다 `worker` = `<결과 폴더 식별자>-<프로세스 식별자>`(각 12자리, 결과 폴더의 `.disk-id`)와 `heartbeat_at`(UTC, 15초마다 전용 연결 — PostgreSQL은 잠금 대기 2초). 프로세스는 살아 있는 동안 `outputs/.workers/<프로세스>.lock`을 운영체제 잠금(fcntl/msvcrt)으로 쥡니다. 같은 결과 폴더의 다른 프로세스는 그 잠금을 얻을 수 있으면 '끝남', 못 얻으면 '살아 있음'으로 압니다. 프로세스 안의 메모리 잠금만으로 다른 프로세스를 보호한다고 하지 않습니다.
- **판정** (`backend/app/recovery.py` 표): 끝난 담당만 — 저장 전 → 실패(그 실행의 임시 파일만 삭제), 기록한 해시와 같은 최종·임시 파일 → 완료, 임시 파일 해시 다름 → 실패, 해시 기록 뒤 파일 없음 → 실패, 최종 파일 해시 다름 → 결과 확인 필요. 근거가 없는 실행(다른 디스크 — 외부 DB를 쓰는 다른 서버, 이전 판)은 **실패로 바꾸지 않고** 신호 10분·기동 30분 뒤 '결과 확인 필요'까지만. 모든 갱신은 조건부(상태·담당이 그대로일 때만) — 조회와 갱신 사이에 완료된 실행·남의 실행은 바꾸지 않습니다. 이전 판 임시 파일·기록 없는 결과 파일은 자동으로 지우지 않습니다.
- **언제**: 기동 때 한 번, 근거가 생길 때만 도는 일회성 타이머 (실행 기록 목록 조회는 예약만 — 쉬는 서버는 DB에 아무것도 보내지 않음).
- **별도 절차**: `python -m app.recovery status` · `recover`(서버를 멈춘 롤백 전 — 종료 0 = downgrade를 막는 행 없음, 2 = 남음, 1 = 오류) · `resolve <실행> --failed` (`docs/DEPLOY.md` 9장).
